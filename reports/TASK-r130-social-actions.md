## 1. ЦЕЛЬ

Игрок в сцене (вне боя) может Влиять, Изучать и Искать; каждое действие даёт
настоящую проверку способности/навыка с Сл из источника, пишет факт в журнал
и **не выдумывает последствий** (никакого автоматического «NPC теперь друг»).
Корпус перестаёт называть эти правила неподдержанными там, где проверка идёт.

## 4. ЧТО ИМЕННО СДЕЛАТЬ

1. **Три действия, три исхода, одна проверка.** Влияние → Убеждение/Обман/
   Запугивание; Изучение → Проницательность/Магия/История/Религия/Природа/
   Расследование; Поиск → Восприятие/Расследование. Игрок выбирает действие,
   навык выбирается по смыслу фразы (интерпретатор) или кнопкой.
2. **Сл берётся из источника, а не из головы.** Порядок: `definition.checks`
   сцены → запись книги в корпусе → `CHECKS` по умолчанию. Придуманную Сл
   писать нельзя: если источника нет, брать значение реестра и **называть это
   в отчёте** как временную величину.
3. **Последствие — факт, не мнение.** Успех/провал пишется как факт журнала
   (кто, что, против какой Сл, итог броска). Отношение NPC, согласие, «NPC
   теперь помогает» — НЕ выставлять автоматически. Это правило проекта:
   предложенное ≠ совершённое (`solo-realms-contracts`), и проверять его
   должен тест.
4. **«Изучить» не выдаёт скрытое.** Результат — не новое знание из головы
   модели, а право хоста показать уже существующий факт сцены (улика, строка
   подготовки). Нет факта — честный отказ «здесь нечего изучить» вместо
   выдумки.
5. **Корпус.** У четырёх правил — законный статус: у тех, где проверка
   действительно исполняется, `engine_subset_verified` + `handler` +
   `blockers: []` + дописанный `formal_behavior`; у `social_check` (реакция
   NPC) — `adjudication_required`, если автоматики отношений нет, и в
   `blockers` прямо написано, чего не хватает. Статусы — только из закрытых
   `enum` (см. `solo-realms-coding`, раздел «Статус в корпусе»).
6. **Экран не обещает недоступное.** В бою этих кнопок нет; вне боя кнопка
   «Изучить» не появляется, если у сцены нет ни одного факта для изучения.
