# r246 — сколько стоит разбор книги: счётчик по прогону

## Что сделано

Одна строка про цену подготовки теперь есть и в ответе сервера, и на экране.

- `solo/preparation_usage.py` (новый): `run_usage(path, run_id)` читает
  `cloud-usage.sqlite3` **только на чтение** (`?mode=ro`) и считает по прогону
  вызовы, входные и выходные токены, отказы и повторы. Связь — по
  `calls.turn_ref` вида `<id прогона>:<ключ части>` (так его пишет
  `PreparationPipeline` → `llm.scope`), поэтому схема леджера не менялась:
  новых таблиц и колонок нет.
- `solo/preparation_pipeline.py`: `status()` отдаёт поле `usage`; путь к
  леджеру берётся из `llm.ledger.path`, иначе — рядом с базами профиля.
  Записей нет / леджера нет → `usage: null`, старые прогоны не ломаются.
- `web/creation.js`: строка итога подготовки на экране черновика дополняется
  ценой прогона (`run.usage.text`).
- `web/prepare-progress.js`: после завершения под полосой остаётся та же
  строка; раньше подпись просто очищалась.
- `web/index.html`: версии `prepare-progress.js` и `creation.js` подняты
  `r241 → r246`, иначе браузер отдаёт закешированный старый скрипт.
- `tests/test_preparation_usage_r246.py`: пять сторожей (см. ниже).

Формат строки: `128 блоков, 632 вызова, 6,5 млн токенов на вход, 177 в отказ`.
Валюты нет — тарифы провайдера меняются, а вызовы и токены остаются фактом.
Отказ — `status IN ('error','invalid_contract','interrupted')`; отмена игрока
(`cancelled`) отказом не считается. Повтор (`retry_of IS NOT NULL`) — отдельное
число.

Ключи и адреса провайдера в ответ не попадают: в `usage` только числа и фраза.

## Приёмка

Живой прогон `f433b435-689b-4e4f-b803-c9cf1a8903a6` (The Rise of Tiamat,
128 блоков). Ответ API против прямого запроса к базе:

| | ответ `/api/creation/runs/{id}` | прямой SQL по `cloud-usage.sqlite3` |
|---|---|---|
| вызовы | 632 | 632 |
| токены на вход | 6 461 237 | 6 461 237 |
| токены на выход | 414 355 | 414 355 |
| в отказ | 177 | 177 |
| повторов | 82 | 82 |
| блоков | 128 (`done`) | `creation_runs.done = 128` |

Строка на экране для этого прогона: `128 блоков, 632 вызова, 6,5 млн токенов на
вход, 177 в отказ`.

Прогон без записей в леджере (старая подготовка): `usage: null`, экран
показывает прежнее сообщение прогона.

Тесты: `tests/test_preparation_usage_r246.py` — 5 passed (числа против прямого
запроса, отказ/повтор/отмена, пустой прогон, отсутствующий леджер, строка на
экране, поле в API). Регресс рядом: `test_preparation_pipeline.py`,
`test_prepare_failures_r241.py`, `test_preparation_finalize_r240.py`,
`test_preparation_resume_r238.py`, `test_preparation_regression_r244.py` —
33 passed; после правки формулировки сообщения — 19 passed в четвёрке файлов.

Синтаксис изменённых скриптов проверен `node --check` (v26.12.1).

### Приёмка на экране (настоящий ход в браузере)

Новая сборка поднята на **копии** живого профиля (порт 19299, `MockLLM`,
без облачных запросов), Chromium открыл экран подготовки, скрипт вызвал
`window.soloOpenCreation('<черновик прогона f433b435>')` и дождался строки:

```
Мир собран из готовых блоков: книга разобрана целиком, вызовов модели не было. · 128 / 128 · 128 блоков, 632 вызова, 6,5 млн токенов на вход, 177 в отказ
```

`console errors: нет`. Снимок — `reports/r246/creation-r246.png`.

### Одна фраза исправлена по ходу

Прогон, собранный из готовых блоков, писал «вызовов модели не было» — правда
про сборку, но рядом со счётчиком читалось как ложь (`632 вызова` в той же
строке). Формулировка стала «…сама сборка прошла без вызовов модели»
(`solo/preparation_pipeline.py:850`). Уже сохранённые прогоны (в том числе
`f433b435` в живой базе) держат старый текст до следующей сборки — их базу
карточка не правит.


## Ограничения и что осталось

1. **Маршрут в карточке назван неточно.** `/api/preparation/runs/{id}` в дереве
   нет; экран подготовки и тесты живут на `/api/creation/runs/{id}`
   (`solo/creation.py:183`). Поле добавлено туда — второй маршрут-дубль не
   заводил. Через `GET /api/creation/drafts/{id}` счётчик тоже виден: он
   приходит в `preparation` (`latest()` → `status()`).
2. **Живой юнит не перезапускался.** В этой сессии Harness блокирует
   `systemctl --user restart` («stop/restart system service»), поэтому живое
   приложение на 19215 всё ещё на `c6488953`. Числа выше получены новой
   сборкой на **копии** живого профиля (копия через sqlite backup API, база
   владельца не тронута): данные прогона настоящие, код — из этого коммита.
   Перезапуск нужен, чтобы счётчик увидел владелец; до него экран старый.
3. **Дерево грязное не только моими правками.** В `web/creation.js` были
   незакоммиченные правки r240 (сборка мира из готовых блоков: `assembly`,
   `resumable`, текст ошибки импорта), в других файлах — тоже. В коммит r246
   вошла **только своя строка** (частичный индекс), чужие правки оставлены в
   рабочем дереве как были: их судьбу решает голова, а не эта карточка.
