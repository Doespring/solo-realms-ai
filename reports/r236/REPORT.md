# r236 — готовые миры: положил файл — играешь через десять секунд

Мир, разобранный один раз, сохраняется файлом `*.soloworld.json` и поднимается
новой кампанией без единого вызова модели. Книга в файл не попадает — едет
только собранное состояние мира.

Живой прогон: локальный сервер `127.0.0.1:19342` (offline MockLLM, своя база и
своя папка миров в скретче задачи, `live/`), Linux. Скриншоты — `reports/r236/*.png`.
Серверные логи прогона: `0` трейсбеков.

### 1. Формат пакета

```
format            "soloworld"            формат, по нему импорт отличает «свой» файл
format_version    1                      версия; новее этой сборки — отказ с просьбой обновиться
created_at        ISO-8601 UTC           когда снят снимок
name, short_name  «Письмо у фонаря», pismo-u-fonarya   имя кампании и имя файла
system            {id, name, edition, version}         механика (2024) — то, чем играют
book              {draft, title, documents, fingerprint, book_fingerprint, prepared_at, status}
                  отпечаток исходной книги из creation_runs.fingerprint
settings          {world.settings (режим, карта), ruleset, preparation (что можно показывать)}
world             места, география (узлы + дороги), наблюдения, часы мира, visited, turn
characters        {hero, engine} — герой и состояние движка Nat20
counts            {locations, routes, npcs}
```

Герой, движок и мир разложены по разным разделам намеренно: импорт собирает из
них живое состояние кампании, ничего не теряя, а человек читает файл глазами.

**Валидация при импорте** (`validate_package`) — до записи в базу: отметка
формата, версия (число, не новее сборки), `world` объектом, хотя бы одно место,
уникальные имена и идентификаторы узлов, дороги только между существующими
узлами, текущее место среди мест, целые неотрицательные часы мира,
`characters.engine` и `characters.hero`, читаемые настройки мира. Пределы:
24 МиБ на файл (проверяется по `content-length` до чтения тела), 400 мест,
800 дорог, 4000 НИП. Битый файл и не-UTF-8 — `WorldPackageProblem`, приложение
отдаёт его как **409 с человеческим текстом** (обработчик `ValueError` в
`solo/app.py:121`), 500 игрок не увидит.

### 2. Две кнопки на экране кампании

Экран называется «Мир кампании» (вид `#world`, «Карта мира» в меню) — это
экран кампании, где живёт сам мир. Блок «Готовый мир» стоит сразу под
заголовком: «Сохранить мир в файл» (скачивание), «Сохранить сюда» (в
библиотеку на сервере), «Загрузить готовый мир» (выбор файла → новая кампания
сразу, разбор книги не запускается).

### 3. Библиотека миров

`runtime/worlds/*.soloworld.json` (папка рядом с базой приложения, в Git не
попадает — `runtime/` в `.gitignore`). Экран «Новое приключение» показывает
список: имя, система, дата, размер, файл, кнопки «Играть» и «Скачать».
Битый файл остаётся в списке с причиной — он не исчезает молча. Список
кэшируется по `(mtime, size)`, чтобы не перечитывать пакеты на каждый показ.
Имя файла на сервере проверяется (`safe_file`): только файл `*.soloworld.json`
внутри папки миров, без путей наружу.

### 4. Кэш по отпечатку

Сделан в r238 (`solo/preparation_pipeline.py:506`) и здесь проверен тестом:
вторая загрузка той же книги находит готовый прогон по `creation_runs.fingerprint`,
пишет «Эта книга уже разобрана, начинаем сразу. Секции взяты из сохранённого
разбора — вызовов модели не было.», части берутся из `creation_parts`. Счётчик
HTTP-пакетов мока (`pdf_smoke_packets`) после второго черновика остаётся `== 1`,
то есть ноль новых вызовов модели. Текст прогона выводится на экране создания
(`web/creation.js:62`).

## Вёрстка

Обе темы приложения — `obsidian` (светлая) и `dark` (тёмная); ширины 375 и 1440.
Скриншоты: `pack-{1440,375}-{obsidian,dark}.png` (экран «Мир кампании») и
`library-{1440,375}-{obsidian,dark}.png` («Новое приключение»).

- 1440: кнопки в строку 176 / 135 / 180 px, блок на всю колонку, карта под ним.
- 375: кнопки столбцом по 341 px (полная ширина), строка библиотеки и её
  заголовок тоже во всю ширину; горизонтальной прокрутки нет
  (`scrollWidth == clientWidth`) на обеих ширинах и в обеих темах.
- Цвета и кегли — из общих переменных темы, своих цветов файл не вводит.

Найдено и исправлено по ходу: на 375 кнопка внутри обёртки выбора файла
оставалась 152 px при полной ширине остальных — `web/worlds.css`, правило для
`.worlds-import` в медиазапросе.

## Границы

- Сохранить готовым миром можно только кампанию Nat20 (у остальных нет
  `state.nat20`) — отказ с текстом, а не пустой файл.
- В пакет не входят история ходов, журнал и память: это новая кампания в том же
  мире, а не копия прохождения. Счётчик ходов новой кампании начинается с нуля.
- `format_version=1`; пакет из будущей версии приложение отклоняет с просьбой
  обновиться, а не пытается прочитать наполовину.
- Пакеты миров лежат в `runtime/` и в Git не попадают (`runtime/` в `.gitignore`).
- Книжные тексты и PDF в коммит не входят.
