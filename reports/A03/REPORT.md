# A03 / F01 — финал мастера вёл в пустое «Новое приключение»

Дата: 08.11.2026. Ветка `work/nat20-engine`, дерево `SoloRealmsAI-Nat20`.
Живая база и профиль не запускались; проверки — на временных базах pytest и
in-process uvicorn с `PreviewMock`/`offline_mock`.

## Факт, с которого начали

Аудит S55–S56: Книги → комплект Тиамат → подготовка Мастера → «Создать героя»,
восемь шагов заполнены, на последнем — «Выбрать героя Nat20». Итог содержал имя,
характеристики, предысторию, старт и 3 предмета, но открылось пустое «Новое
приключение» без описания и материалов.

## Причина

Две машины состояний с одним сломанным ребром:

1. `web/preparation.js:step===7` вызывал `window.soloOpenCreation()` **без id**,
   а `creation.js::open(id=null)` в этом случае делает `POST /creation/drafts` —
   новый пустой черновик. Восемь шагов мастера оставались в черновике подготовки.
2. `CreationService.get()` вызывал `owned()`, который для готового черновика
   мастера возвращал `adopt()['draft']`, то есть **вид запуска**, и внешний `get()`
   снова читал у него `['body']` → `KeyError: 'body'` → 404. Открыть сохранённый
   черновик мастера по id из библиотеки было нельзя вообще (нашёл при проверке
   второго входа).

## Что сделано

**Один контракт передачи — `solo/creation_handoff.py` (новый).**
`record(preparation, draft_id, library)` — единственная запись, которую читают
старый мастер и запуск: `draft_id`, `module_id`, `hero_draft` (текст игрока, без
пустых полей), `equipment` + `equipment_items` (русские имена), `start`, `opening`,
`book` (вырезанная ли глава), `revision`, `flow`, `campaign`, `missing`/`ready`.
`missing_parts()` называет каждую недостающую часть и **номер шага мастера**, которым
она заполняется. `verify()` сверяет части, пришедшие с экрана, с сохранённым
черновиком до создания чего-либо. `carry()` записывает одобренные предметы в
кампанию (`state.preparation.equipment` + журнальное событие) один раз на черновик;
событие не считается ходом героя там, где журнал это умеет (`counts_as_turn` из
работы L02), а на сборке без этого флага остаётся обычной записью — код коммита
не зависит от незакоммиченной правки соседнего юнита.

**Сервер.** `solo/creation.py`: `owned()` переводит готовый черновик мастера в
общий контракт **на месте** (`flow: legacy → simple`, без копии), недозаполненный —
отказывает списком частей; `adopt()` — переход последнего шага (проверяет
`revision`, `module_id`, `hero_draft`, `equipment`, привязывает файлы книги к
черновику); `handoff()`; `get()/view()` разделены (чтение по id мигрирует, листинг —
только проекция, ревизию не двигает); `list()` показывает готовый черновик мастера
в «Моих приключениях» ещё до первого запуска. Ручки:
`GET /api/creation/drafts/{id}/handoff`, `POST /api/creation/drafts/{id}/adopt`;
`GET /api/creation/drafts/{id}` отдаёт `handoff`.

`solo/prototype_ui.py`: `NewGameInput.module_id/hero_draft/equipment` проверяются
`verify_handoff` **до** создания кампании в обеих ветках запуска; после создания
`carry()` отдаёт экрану те же предметы.

`solo/prototype_prepared.py`: `bind_library_module` берёт стартовое место и
открывающую сцену из ответов мастера (`start_name`, `opening`), а не подменяет их
первой страницей книги.

`solo/playable_ui.py`: предметы мастера видны в листе героя рядом с комплектом
Nat20 с пометкой `source: 'preparation'`; механика остаётся за движком.

**Экран.** `web/preparation.js`: последний шаг шлёт `adopt` с `draft_id, revision,
module_id, hero_draft, equipment` и открывает **тот же** черновик
(`soloOpenCreation(id, handoff)`); если `ready:false` — блок «Чтобы начать историю,
дозаполните: …» со списком и кнопкой «Дозаполнить: <шаг>»
(`window.soloResumePreparation(id, step)` — тот же id, тот же черновик).
`web/creation.js`: `open(id, handoff)` запоминает передачу и рисует её
(`#creation-handoff` — черновик, приключение, герой, старт, предметы); при 409 от
сервера показывает «Этот черновик ещё не готов к игре» с кнопкой «Вернуться в
подготовку» вместо пустого экрана; для проверенной главы книги — кнопка «Выбрать
героя Nat20 и начать по книге» (законный старт без подготовленного мира);
`soloOpenPreparedWorkflow` (карточка «Создать героя» в библиотеке) при отсутствии
мира открывает тот же черновик с передачей, а не отказывает.
`web/wizard.js`: `module_id`, `hero_draft`, `equipment` уходят в запуск явно; имя и
предыстория мастера подставляются в редактор, предметы видны на шаге снаряжения.

## Приёмка (Q01, Q02)

| № | Требование | Чем закрыто |
|---|---|---|
| 1 | 8 шагов → «Начать историю» → имя героя, старт, 3 предмета (3 из 3) | браузер 390 px: `#play` показывает «Пламя над Гринестом» и «Лира»; `state.hero.name='Лира'`, `state.location='Гринест у заставы'`, `state.preparation.equipment` = 3, лист героя — 3 с `source:'preparation'` |
| 2 | Черновиков после прохода — 1, не 2 | `GET /api/creation/drafts` = `[draft]`, `GET /api/preparation/drafts` = `[draft]` до и после старта |
| 3 | Возврат назад не теряет введённое (шаги 3 и 7) | браузер: правка старта и сцены на шаге 3 → «Продолжить» → «Назад» — значения на месте; 3 отмеченных предмета на шаге 7 → «Назад» → «Продолжить» — те же 3 |
| 4 | Второй вход из книги — те же 3 из 3 | браузер: обработчик карточки модуля `soloChooseAdventure(bundle, module)` заводит новый черновик мастера, восемь шагов заполняются в UI, «Выбрать героя Nat20» → история с тем же 3 из 3; `pytest` — второй проход по той же книге/модулю даёт 3 из 3 |

Замечание по шагу 3: правка старта снимает подтверждение подготовки (так и было
задумано в мастере), поэтому игрок подтверждает его снова; без этого запуск
честно отвечает «Подготовка книги не подтверждена» и даёт кнопку дозаполнить.

## Ограничения

* Второй вход в браузере идёт через обработчик, который висит на кнопке
  «Создать героя» карточки модуля (`window.soloChooseAdventure(bundle, module)`);
  сама кнопка лежит за экраном закрытой подготовки Мастера (спойлеры), его в
  тесте не открывали. Дальше путь целиком экранный: восемь шагов, «Выбрать героя
  Nat20», редактор, история.
* Предметы мастера — запись игрока рядом с листом Nat20 (`source:'preparation'`),
  а не часть сборки движка: числа и владение по-прежнему считает Nat20.
* Недозаполненный черновик не мигрирует и не попадает в «Мои приключения»; его
  части называет запуск по кнопке последнего шага.
* Живая пользовательская база и профиль модели не запускались; проверки — на
  временных базах (`PreviewMock`, `offline_mock`).
* Коммит `c0b05bb9` проверен отдельно в чистом `git worktree` на HEAD (без
  незакоммиченных правок соседних юнитов): `tests/test_master_handoff_f01.py`
  8 passed — коммит самодостаточен.
