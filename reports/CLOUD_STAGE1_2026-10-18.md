# Этап 1 — контекст, cache и блокировки

18 октября 2026. Вводная владельца прочитана полностью. Выполнен только этап 1;
движок, этапы 2/3, UI, Drive, ROADMAP, EXE/ZIP не менялись. Живых/платных вызовов 0.

## Изменения

- `cloud_context.py`: планировочная эвристика ASCII/3.2 + кириллица/2.4,
  округление вверх и **25% запаса**. Остальной Unicode консервативно считается
  по его байтам. Framing 128 и отдельное image allowance 4096 сохранены; base64
  не становится текстовыми токенами, native schema учитывается отдельно один раз.
  UTF-8 bytes остаются диагностикой, не числом токенов. Метод явно `exact=false`:
  это не модельный токенизатор и не доказанная верхняя граница.
- Существующий стабильный system-prefix сохранён: нормализация старого маркера
  постоянна, текущий лимит слов добавляется в конец user. Byte-equality двух
  системных сообщений при разных длинах ответа проверена настоящим mock HTTP.
- `cloud_settings.py` / `cloud_setup.py`: `cache_read_per_million` поддержан вместе
  с прежним `cached_input_per_million`. Разные одновременные значения отвергаются;
  диапазоны/конечность проверяются. При смене маршрута оба тарифа очищаются.
  Неуказанное новое поле исключено из model_dump, сохраняя старые config dumps.
- `cloud_cost.py`: при валидном явном cache hit используется явный тариф либо
  **0.1 × обычного входа** согласно новому поручению. Без hit/полного валидного
  usage скидка не выдумывается. Цена фиксируется при reserve; сам reserve по-прежнему
  покрывает полный вход без будущего cache hit. Более дорогой cache-тариф тоже покрыт.
  Aggregate vision usage не получает неподтверждённую текстовую cache-скидку.
- `cached_tokens` добавлен в финальные metrics/calls как совместимый alias
  `cached_input_tokens`: это часть input, а не дополнительный расход. Nullable
  колонка добавляется идемпотентно; старые известные счётчики копируются без
  изменения исторических сумм. Миграция проверена только на собственном synthetic DB.
- `cloud.py`: словарь локов кампаний; прежнее имя `lock` осталось только fallback
  для вызовов без кампании. Разные кампании перекрываются по времени, одна кампания
  и unscoped-вызовы сериализуются. last_narrative/policy и текущая метрика изолированы
  ContextVar; глобальная история metrics сохраняется, а metrics[-1] внутри caller
  относится к его запросу. Contract-error одной кампании не портит другую.

BEGIN IMMEDIATE, integer microcurrency, общий/остальные денежные пределы,
одноразовые подтверждения, reserve/failure/cancel и приоритет фактического счёта
провайдера сохранены. Отмена без usage сохраняет резерв, освобождает собственный
лок; соседняя кампания и повторный вызов работают. Счёт выше резерва не обрезается;
последующий запрос учитывает его полностью. Оценочный reserve не обещает точного
максимума реального счёта при неизвестном токенизаторе.

## Синтетические примеры

| Пакет | Символы | UTF-8 bytes | Старый план | Новый план |
| --- | ---: | ---: | ---: | ---: |
| Русская сцена | 4104 | 7508 | 8575 | 2176 |
| JSON с русским текстом | 1593 | 2817 | 3298 | 911 |

Framing включён. Это сравнение алгоритмов на заданном тексте, не калибровка по
живой модели. При input=1000, cached=800, output=200; тарифах 2/4 за млн:
default cache 0.2 даёт 0.00136; явный cache 0.5 — 0.0016; без hit — 0.0028.
Фактический счёт провайдера имеет приоритет перед этими расчётами.
Прежняя политика отчёта 17 октября «нет cache-тарифа — нет скидки» заменена
текущим прямым поручением владельца; это не подтверждение тарифов провайдера.
