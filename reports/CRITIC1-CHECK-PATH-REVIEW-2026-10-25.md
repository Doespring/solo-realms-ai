# Независимый критик №1: проверки и навыки через чат — обзор механики

Дата: 25.10.2026. HEAD: 9b67dfd (рабочее дерево с правками). Проверено чтением исходников и локальными прогонами в venv (.venv/Scripts/python.exe, pydantic 2.14.1), без вызовов API и без живой базы. Временные пробники удалены. Код не правился.

## 0. Главный вывод

Заявленный путь **не реализован**. В игровом чате нет ни `IntentPacket`, ни типизированной команды Nat20 для проверок, а «тройка слоёв» сводится к шаблонным порогам.

| Что заявлено | Что фактически |
|---|---|
| реплика → IntentPacket → команда → Nat20 → сохранение → рассказчик | `Game.route` → `natural.quick` / `llm.interpret` → `Plan` → `natural.resolve` → `RulesetEngine.check` (свой d20 на `secrets.SystemRandom`). Nat20 не вызывается. |
| origin 'source' только при книжной проверке с происхождением | 'source' ставится и на «стартовую сцену» (без страницы), а разбор даёт 512/1000 честного прыжка мимо броска |
| невозможное не становится возможным | «Прыгаю через пропасть, чего бы это ни стоило» → «Исход ясен без броска» (ни один из трёх исходов не невозможен) |
| бросок при неопределённости | при отсутствии `dc` шаг `check` сразу помечается `settled=True` («Исход ясен без броска»), даже когда исход явно неясен |


**Сводка/уточнение:** само вычисление броска (`rulesets.check`) выполняется, но в запись события не попадает (Д14). Игрок видит «Проверка» без числа, и «хороший результат» ни подтвердить, ни сохранить нельзя.

Пункты 1 и 2 поручения (слой origin и удаление отказа по `check_for`) действительно есть в диффе. Пункты 3 (Nat20), 4 (невозможное) и 5 (команда Nat20) не выполнены ни в `solo/nat20_api.py`, ни в `solo/game.py`.

## 1. Дефекты (путь обрывается / белый список)

**Д1. Путь IntentPacket/команда Nat20 не используется игровым чатом.** 
`solo/game.py:962-978, 1017-1020` — `play_command` строит `Plan` и отдаёт его в `store.stage`; `solo/storage.py:229-234` вызывает `natural.resolve`; `solo/natural.py:326-329` — `rules.check`. `solo/cloud.py:94` (где собирается IntentPacket) — отдельный путь. 
*Ожидается:* при осмысленной проверке — типизированная команда `check` в Nat20 (`solo/nat20_worker.py:283-290`), затем сохранение результата и рассказчик. 
*Как проверить:* в системном журнале любого `check`-результата нет ни `native_result`, ни `command`, ни `request_id` команды Nat20; `result['ruling']` говорит «бросок выполняет движок» (`natural.py:331`).

**Д2. `natural.resolve(..., scenario_checks=False)` вообще не вызывает `check_for`.** 
`solo/natural.py:320`: при `scenario_checks=False` берётся `(step if step.kind=='check' else None, None, 'master')`. Итог: шаг `check`, прошедший через `guard` со стёртыми `ability/dc` (`natural.py:90`), попадает в `rules.check` и падает `ValueError('Укажите характеристику и Сл для проверки в редакторе плана')` (`solo/rules.py:31`). 
*Ожидается:* каждый `check` из интерпретатора получает либо книжную проверку, либо решение мастера, либо «без броска» с origin в результате. 
*Как проверить:* `resolve(state, Plan(steps=[Step(kind='check',text='Вспоминаю герб',ability='intelligence')]), scenario_checks=False, resume=False)` → исключение (воспроизведено).

**Д3. Ранний отказ по `check_for` убран, но вместо уточнения ложное «Исход ясен без броска».** 
`solo/natural.py:321-324, 327-328`: если проверки нет — `check_step=step` и сразу settled. Но `game.py:1003-1013` уже записал `dc/ability` на первый шаг, а `guard` (`natural.py:130`) вызывает `check_for` до этого — второй раз строка не обновляется. Реальный исход: шаг разобран, а числа нет. 
*Ожидается:* «непонятно» → уточнение «Что именно вы хотите узнать?»; «очевидно» → исход рассказчика; «невозможно» → отказ. 
*Как проверить:* `resolve(base, Plan([Step(kind='check',text='Пытаюсь вспомнить герб')]))` → `settled=True` (воспроизведено).

**Д4. `place.checks` всё ещё управляет mechanics-adapter в `command_engine`.** 
`solo/command_engine.py:79-80` (`available_checks=sorted(...place.get('checks'...)) or _BASE_CHECKS()`) и `solo/command_engine.py:180-194` (`value=place.get('checks',{}).get(action.check_id)`; `origin='source' if source else 'master'`). Со стороны `play_screen` перечень расширен реестром (`solo/play_screen.py:56-59`), а `nat20_api`/snapshot — исправлены. 
*Ожидается:* ни `command_engine`, ни DTO не берут `place.checks` как перечень; DTO даёт `definition.checks`/`CHECKS`. 
*Как проверить:* временно очистить `place['checks']` — `command_engine.snapshot().available_checks` вернёт полный `_BASE_CHECKS()`, т.е. книга по-прежнему определяет, что можно сделать.

**Д5. Ответ команды проверки — «Укажите навык…», не уточнение по смыслу.** 
`solo/command_engine.py:189`: `raise ValueError('Движок не знает такой проверки. Назовите навык…')`. Старый `refusal_text` (`solo/game.py:144-157`) не доходит до зарегистрированных маркеров, поэтому видно «Мастер отказал: действие невозможно…».

## 2. Число механики считает не Nat20 (и нет записи происхождения)

**Д6. Бросок — `RulesetEngine`, а не Nat20, и «проверка напечатана материалом» лжива.** 
`solo/natural.py:326-331` → `solo/rulesets.py:58-79` (собственный d20 на `secrets.SystemRandom`). `result['ruling']` = «Проверка напечатана материалом… бросок выполняет движок» — это второй калькулятор (нарушение AGENTS.md). 
*Как проверить:* в `results` отсутствуют `native_result`, `dice` из Nat20, `command`.

**Д7. Сложность 12 из `travel.NODES` записана как «источник» и зашита в код, не в материал.** 
`solo/natural.py:224-228`: `origin='source'`, `source_ref='базовая сцена стартового места'`, `dc=12` — это решение Solo по умолчанию, страницы книги нет. Для героя 1 уровня `dc=12` при профицитном навыке («Ищу следы» → `survival`) фактическая доля успеха 51%, а «обычный» `Named DC 15` не взят. 
*Ожидается:* `origin='master'` + `source_ref=''`. 
*Как проверить:* воспроизведено — `check_for` на `travel.NODES`-месте даёт `origin='source'`; 400 прогонов `RulesetEngine.check` для `dc=12, skill='survival'`: успех 205/400 (≈51%).

**Д8. Нет валидации, что `source/page` — настоящая страница материала.** 
`solo/natural.py:213-223` берёт `value['triggers']` и `_provenance` — любые строки. Форма `place['checks']` нигде больше не создаётся (`solo/prepared_world.py` вообще не содержит `triggers`), `solo/prototype_ui.py:39-57` создаёт `definition.checks`, а не `place.checks`. 
*Ожидается:* проверка сверки `value['source']`, `page` с фактом индекса источника или `origin='master'` без `source_ref`.

## 3. Отказ вместо уточнения / бросок не там, где нужен

**Д9. Осмысленный осмотр/поиск съедается как объект-осмотр, затем «уточнение по объекту».** 
`solo/natural.py:212` гейт `^(?:ищу|осматриваю…)` сразу режет все «Осматриваю …», а `solo/interactions.py:88` даёт «Состояние этого объекта не зарегистрировано». Воспроизведено: `quick('Осматриваю стену в поисках тайника')` → `observe` шаг → `resolve` → `needs_context`. 
*Ожидается:* если неопределённость есть — проверка (investigation) или исход рассказчика; уточнение — только при реальной неоднозначности. 
*Как проверить:* `natural.resolve(state, natural.quick('Осматриваю стену в поисках тайника', state))`.

**Д10. «Броски почти невозможного» назначаются там, где бросок не нужен, и не назначаются там, где нужен.** 
`natural.py:167-169` `NAMED_DC` содержит «почти невозможн» = 30: высокая Сл по реплике игрока, а не отказ мастера. Для `speak` при почти невозможном убеждении — проверка 30, при очевидном «убеждаю стражника пропустить бесплатно» — тоже 30 (и origin master). 
*Ожидается:* «почти невозможное убеждение» — не бросок, а несбыточный запрос. 
*Как проверить:* `check_for(Step(kind='speak',text='Убеждаю короля отдать корону почти невозможным доводом'), …)` → `dc=30`.

**Д11. Триггеры сверяются подстрокой, в том числе с отрицанием.** 
`solo/natural.py:214` `any(norm(word) in text …)`: «Не уговариваю стража…» и «Обсуждаю, что страж охраняет» тоже дадут проверку `origin='source'`, если в `place.checks` есть триггер «страж». Воспроизведено на синтетическом `place`. 
*Ожидается:* совпадение по границе слова/смыслу и без отрицания.

**Д12. Пропадает проверка `investigation/osmotr` и умность — «Проверяю…»/«Разглядываю…» вообще не получают броса.** 
`natural.py:211-212`: `check` мимо книги → `master_ruling`; `room_for_roll` (`natural.py:177-180`) содержит «разглядываю|осматриваю|ищу|вспоминаю», но не содержит «прыгаю|перелезаю|открываю|взламываю». Соответственно «Прыгаю через пропасть» — без броска, а «Пытаюсь перепрыгнуть» — бросок. Ещё «Торгаюсь» → `None` (нет броса), хотя `room_for_roll` содержит «торгуюсь». 
*Как проверить:* `check_for` на текстах «Торгуюсь…», «Пытаюсь перепрыгнуть…», «Прыгаю через пропасть…».

## 4. Сохранение и логирование результата

**Д13. `origin`/`source_ref`/`ruling` не доходят до сохранённого события.** 
`solo/natural.py:332`: итоговый словарь собирается заново как `{'type':step.kind,'text':…}`. В `solo/game.py:386-387` пишется `text`/outcome, а `origin`, `ruling` не копируются — ни в `executed` (писатель), ни в память (`solo/memory.py:144-145`). Удалить линию проверки нельзя, и происхождение не остаётся в журнале.
*Как проверить:* в `solo/game.py:363-390` (сборка `packet` для рассказчика) и `solo/memory.py:144-145` (`kind=='check'`) поля `origin`, `source_ref`, `ruling`, `formula` не читаются вовсе; в `solo/natural.py:332` они и не доходят до `results` (см. Д14).

**Д14. Результат броска не доходит до результата шага (перезапись без `continue`).** 
`solo/natural.py:329-332`: после ветки `check` `result` дополняется `origin/source_ref/ruling`, но затем (без `continue`, в отличие от `natural.py:309-319`) выполняется `results.append({'type':step.kind,'text':step.text,'target':step.target})` — брошенный результат заменяется голым словарём. Воспроизведено: `RulesetEngine.check(...)` напрямую → `{'type':'check','success':False,'dice':[8],'total':9,'formula':'d20 +1 = 9 против Сл 10','ruling':...}`, а `natural.resolve(...)` для такого же шага → `{'type':'check','text':'Ищу следы','target':''}` (ни `success`, ни `dice`, ни `origin`). 
*Ожидается:* после ветки `check` — `results.append(result)` и `continue`; `success/dice/bonus/dc/formula/origin/source_ref/ruling` остаются в событии. 
*Как проверить:* `natural.resolve(st, Plan(steps=[Step(kind='check',text='Ищу следы',dc=10,ability='wisdom',skill='survival')]))` → бросок не виден (воспроизведено).
