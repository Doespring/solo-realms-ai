# A07 / F12 / P1 — фокус не теряется в диалогах

Дата: 09.11.2026, 00:40–01:25 UTC. Ветка `work/nat20-engine`, дерево `SoloRealmsAI-Nat20`.
Карточка: аудит 08.11, снимки S74–S75.

## Что было не так

1. `<dialog>` в этом браузере не замыкает Tab: после последнего элемента окна
   `document.activeElement` становился `BODY` (в карточке предмета — за два Tab от
   «Выбрать для реплики»). Escape при этом работал, поэтому дефект не выглядел поломкой окна.
2. Селектор действия пересобирался на каждый `change`: `draw()` делал
   `body.replaceChildren()` и выбрасывал сам сфокусированный `<select>`, фокус уходил в `BODY`.
3. Подложка под окном оставалась достижимой мышью и Tab; фокус после закрытия не возвращался
   инициатору.

## Сделано

**`web/focus.js` (новый, 195 строк)** — поведение надевается на
`HTMLDialogElement.prototype.showModal/close`, поэтому работает для всех окон, которые
создаются в рантайме (`chronicle.js`, `game-screen.js`, `adventure.js`, `navigation.js`),
без правки каждого экрана:

- Tab/Shift+Tab ходят по кругу внутри верхнего окна; порядок как у браузера
  (положительный `tabindex`, затем разметка); окно без фокусируемых элементов получает
  `tabindex="-1"` и держит фокус на себе, атрибут снимается при закрытии.
- всё, что под верхним окном, получает `inert`; контейнер, внутри которого лежит окно, не
  гасится; прежние значения `inert` возвращаются при закрытии (карта чистится, а не живёт
  вечно).
- закрытие возвращает фокус инициатору; если инициатора перерисовали — первому
  достижимому элементу активного экрана (раньше — только поле реплики на экране `play`).
- Escape не перехватывается, когда фокус внутри окна: закрытие и событие `cancel` делает
  браузер, поэтому окно может отказаться закрываться через `preventDefault`. Синтетическое
  закрытие осталось только для случая «фокус уехал из окна».
- окно, убранное из документа без `close()`, снимается со стека наблюдателем
  (`MutationObserver` живёт только пока открыто окно): иначе подложка навсегда осталась бы
  `inert`, а Tab и мышь — мёртвыми.
- повторный `showModal()` на уже открытом окне не затирает прежнего инициатора элементом
  из самого окна.

**`web/prototype-actions.js`** — список действия стал постоянным узлом: перерисовываются
только `.prototype-action-fields`, поэтому `change`/ArrowDown больше не выбрасывают
сфокусированный `<select>`. Перед обновлением запоминается поле, после — фокус возвращается
по `aria-label`, а показанные значения полей восстанавливаются из собранных `values`
(раньше при перерисовке они терялись). Ветка ошибки больше не оставляет видимую панель без
формы.

**Рамка фокуса 2 px.** Глобальное правило `:focus-visible` в `web/themes.css` уже было
2 px до этой карточки — оно и держит боевые экраны. Добавлено недостающее: композер
(`#action-form:focus-within`, у `textarea` был `outline:none`), визард (было 1 px → 2 px),
сетка полей параметров действия.

прогон не дошёл до итогового ответа (обрыв хода), поэтому спорные пункты перепроверены кодом
и прогоном здесь. Что было исправлено после ревью:

| Находка | Итог |
|---|---|
| окно, убранное без `close()`, навсегда оставляло подложку `inert` | исправлено (наблюдатель + снятие со стека), покрыто тестом |
| повторный `showModal()` затирал инициатора | исправлено, покрыто тестом |
| возврат фокуса в поле параметров был мёртвым кодом, значения полей терялись | исправлено (запоминание до скрытия панели, сохранение `values`, восстановление значений), тест переписан на настоящий `solo:render` |
| Escape в capture обходил `cancel`/`preventDefault` и закрывал окно синтетически | исправлено: при фокусе внутри окна закрывает браузер, покрыто тестом |
| запасной возврат фокуса работал только на экране `play` | исправлено: первый достижимый элемент активного экрана |

## Ограничения (честно)

- Приёмка Q19(3) на **боевой** странице невозможна: панель действий снята с полной страницы
  решением владельца 08.11 (`tests/test_chat_only_shell.py`, `REMOVED_FROM_FULL_PAGE`).
  Селектор проверен на стенде, где модуль подключён тем же файлом, что и в приложении.
- Браузерные регрессии `tests/test_prototype_ui.cjs`, `tests/test_stage2_ui.cjs`,
  `tests/test_native_parameters_ui.cjs` запускают `chromium.launch({channel:'msedge'})` —
  на этой Linux-машине они не стартуют, поэтому **не прогонялись**. Панель действий в них
  не входит в боевой путь (снята с полной страницы), а перерисовку полей покрывает A07-тест.
- Светлая тема тестом не измеряется (тест всегда ставит `solo-theme: 'dark'`); правило
  `:focus-visible` в `themes.css` общее для обеих тем, но замер колец в светлой теме —
  ручной, в тест не входит.
- Один Tab-стоп `BODY` из 14 на игровом экране — это граница страницы (уход в хром
  браузера), а не дефект; в отчёте он виден, замолчан не был.
- Полный `pytest tests/` не гонялся: правка только в `web/`, прогон 16 сторожей и живого
  браузера достаточен для этого диффа. Общего регресса «всё дерево» в этой карточке нет.
