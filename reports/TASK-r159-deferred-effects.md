# r159 — сценарные эффекты в кампании Nat20 исполняются, а не копятся в deferred

## ЦЕЛЬ

Сценарные эффекты `check` / `table` / `resource` / `reward` из книги доезжают до
игры Nat20: проверка ставится игроку, награда/ресурс меняют состояние, таблица
бросается — тем же движком, а не старым `RulesetEngine` и не «в ожидании».

## ОТКУДА ЗАДАЧА (проверено, не перевыводить)

r158 (`d2eb422`) закрыл дыру «сценарный переход исполнял эффекты старым
`RulesetEngine` для кампании Nat20». Закрыл он её **отложенностью**:
`engine_event` передаёт `mechanics='nat20' not in state`, а `tick` пишет такие
эффекты в `state['adventure']['deferred']` с уведомлением «ожидает игрового
экрана Nat20». **Исполнителя у `deferred` нет ни одного.** То есть эффект
больше не исполняется чужим движком (это правильно), но и не исполняется
никаким: карточка гласит «нужна отдельная карточка».

Живой прогон прораба 01.11 (свой инстанс, порт 19601, коммит `d2eb422`,
офлайн-мок, Hoard of the Dragon Queen RUS): кампания `/api/nat20/campaigns`
→ attach модуля 02 (200) → карта стр. 19 подтверждена → ход «Показываю игрокам
карту лагеря налетчиков» → `resolved`, текст «…на столе, стр. 19», картинка
игроку 200, 2047×1526, контраст 9..255. `state['adventure']['deferred']` —
`null` (эффектов этого класса ход не дал, но и исполнителя нет).

## ЧТО СДЕЛАТЬ

1. Найти, кто читает `state['adventure']['deferred']` — сейчас никто
   (`grep -rn "deferred" solo/`).
2. Дать эффектам Nat20-кампании путь исполнения через Nat20: `check` →
   `command-turn`/экран Nat20 с бросом и готовой формулой (как в r133),
   `reward`/`resource` → запись в состояние кампании (инвентарь/счётчики),
   `table` → бросок с таблицей из книги и цитатой страницы.
3. Очередь `deferred` разбирать по порядку и **не терять** при повторном тике;
   повторный `tick` не должен дублировать эффект (идемпотентность по
   `request_id`/id эффекта).
4. Уведомление «ожидает игрового экрана Nat20» оставить только для эффектов,
   которые действительно требуют экрана (например, атака), а не для всех.
