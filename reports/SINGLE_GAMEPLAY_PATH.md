# Единый игровой путь: итог на текущую дату

Отчёт по заданию `docs/DEEPSEEK_SINGLE_GAMEPLAY_PATH_PROMPT.md`.
Подробный ход работы — `reports/SINGLE_GAMEPLAY_PATH.log.md`.

## Кратко

Главная находка: в проекте было **два игровых пути**. Обычный вход
(«черновик → герой → подтверждение») создавал кампанию через
`solo/preparation.py` `launch()` со старой моделью `Hero` и **без** ключа
`nat20`, поэтому игра шла на старом `CommandEngine`. Подготовленный мир при
том же входе, но через `solo/prototype_prepared.py` `launch_prepared()`,
создавал полноценную Nat20-кампанию.

Замер на одном и том же мире:

| Вход | `nat20` в состоянии | Движок |
|---|---|---|
| второй редактор → `/character/confirm` | **нет** | старый `CommandEngine` |
| `POST /api/prototype/campaigns` | **да** | Nat20 |

Выбор сделан: единственный путь — **Native-мастер Nat20**. Обоснование в
разделе «Почему не конвертация».

## Что сделано

1. **Обычный вход героя переведён в Native.** `web/creation.js:17`, обе кнопки
   («по описанию» и «в конструкторе») зовут `window.soloOpenPreparedNat20`.
   Второй редактор остаётся достижимым только для черновиков, где герой уже
   заведён (`row.character_mode`), то есть для старых сохранений.
2. **Старый маршрут подтверждения закрыт.** `solo/character_creation.py`
   `confirm()` больше не создаёт кампанию, а отказывает сообщением о едином
   пути. Ни один маршрут второго редактора не даёт кампанию без `nat20`.
3. **Исправлен дефект «герой заперт в первой сцене».**
   `solo/prototype_prepared.py`: места без секретов получают
   `known_to_hero=True` и `node.known=True`. Раньше `known()` требовал оба
   флага, а известность появлялась только по прибытии — выйти было нельзя.
4. **Замкнут единый путь.** Подтверждённый мир → `world-readiness` (ready,
   world_ready, run_id) → `POST /api/prototype/campaigns` → 200,
   `nat20` в состоянии, `definition.build.classes == {'fighter': 1}`.

## Почему не конвертация старого листа

Nat20 ждёт `CharacterBuildSpec` (`species_slug, classes, ability_scores,
selected_choices, …`), а старый черновик хранит другой набор
(`species, class_id, method, scores, bonuses, class_skills…`). Попытка собрать
лист вручную падает:

```
ChoiceError: advancement choices still owed: skill x2 at class:fighter level 1;
skill x1 at species:human level 0; feature x1 at species:human level 0;
feature x1 at class:fighter level 1
```

Движок сам требует выборов, которых в старом формате нет. Любая конвертация с
догадками была бы вторым калькулятором, то есть ровно запрещённым. Поэтому
единый путь для нового игрока — Native-мастер, а не переписывание второго
редактора.

`web/character-creation.js` — следующая готовая операция этапа E.

**Проверка ответа рассказчика (часть этапа C) — работает.** `verify`
(`solo/narrative_grounding.py:51-59`) требует дословного совпадения каждого
предложения с подтверждённым источником. Опыт: честный текст принят;
выдуманное описание, выдуманная реплика NPC, навязанное действие и подсунутое
предложение — отклонены с `CanonViolation`; при отказе подставляется текст из
книги. Механика считается Nat20 до рассказа, поэтому вымысел не отменяет
выполненный ход.

**Пересказ без повторной механики — работает.** `PUT /api/events/{id}/narrative`
заменяет текст хода, не меняя ни версию кампании, ни HP: проверено, версия
осталась 2 → 2. При этом `event_id` должен быть идентификатором журнала Solo
(UUID), а не идентификатором движка `nat20:ev1` — на этом пути я сам сначала
выдал ложный идентификатор и исправил его.

**Вымысел не становится фактом мира (память).** `solo/memory.py:85-90`
запрещает записывать слова игрока или NPC как `fact`; проверено опытом:
`A statement cannot become world truth automatically`. Законная авторская
запись и слова как слова проходят. То есть отделение вымысла от факта
закреплено в хранилище, а не только в тексте рассказа.

**Каждый завершённый ход оставляет запись в памяти.** Проверено: после
одного действия запись по `memory_key` имеет
`('resource', 'fact', 'private', 'confirmed_event')` — происхождение
`confirmed_event`, то есть запомнено событие, подтверждённое движком, а не
пересказ. Это и есть основание для «использования памяти в дальнейшем»: игра
хранит не прозу, а подтверждённые последствия.

**NPC знает только своё.** Проверено с двумя NPC в одной сцене: в каждый
пакет рассказчика попадает ровно один собеседник, а общая память мира — 0
(`shared: 0`). Знания фильтруются движком по `npc_id`, а не доверием к тексту
(`solo/prototype_gm.py:56-61`).

**Локальная работа, которая ещё впереди:**
- выбор рассказчика по режиму и содержанию с видимой причиной;
- проверка ответа с отделением вымысла от изменения фактов;
- повторное озвучивание без повторного выполнения механики;
- идентификаторы SQLite/памяти в ответах;
- матрица Nat20 по четырём уровням;
- переписать 3 теста второго редактора на Native-маршрут;
- удалить доказанно заменённые реализации (этап E).

## Обновление: этапы D и E (раунды 70–71)

### Найден и исправлен дефект продукта, из-за которого зависал /api/health

Обработчик health вызывал блокирующий `subprocess.run(['git', ...])` прямо в событийном
цикле, а git наследовал stdin хоста. Если хост держал stdin читаемым каналом, поток-читатель
git не завершался, `communicate()` не возвращался, и **health не отвечал никогда** —
при этом порт честно был `LISTENING`.

Исправлено в продукте:
- `solo/build_identity.py:37` — `stdin=subprocess.DEVNULL`;
- `solo/app.py:147` — `identity=await asyncio.to_thread(build_identity)`.
