# r156 — модель видит карту: разбор карт не в 384 px

## ЦЕЛЬ

Для разбора карт изображение, которое уходит модели, рендерится крупнее 384 px
по длинной стороне (предлагаю 1024–1536 px с урезанием по лимиту запроса), а
для остальных картинок прежний предел остаётся. Причина: `solo/analysis_images.py`
режет всё до ≤384 px, поэтому «найди комнату 3 на карте» физически невозможно —
подземелье в 384 px нечитаемо (записано в reference `adventure-pdf-and-materials.md`).

## ЖЁСТКИЕ ЛИМИТЫ, КОТОРЫЕ НЕЛЬЗЯ ПРЕВЫСИТЬ

- не больше **2** картинок на запрос;
- `data:image/png;base64`, длина URL **≤150 000** символов — это жёсткий
  лимит провайдера. Считать длину ДО отправки и урезать качество/размер, а не
  надеяться, что пройдёт.

## ФАЙЛЫ

- `solo/analysis_images.py` (основная правка: параметр размера для `kind='map'`)
- точка вызова разбора карт (найти: `grep -rn 'analysis_images' solo/`)
- тест: `tests/test_map_image_scale.py`

## НЕ ТРОГАТЬ

- `vendor/nat20/**`, `PATCHES.json`.
- Рендер карты для ИГРЫ (2048 px, `/api/campaigns/{c}/adventure/materials/{id}?width=2048`) — он уже правильный.
- Предел 384 px для иллюстраций и страниц — оставить.

   Тест обязан проверять: длинная сторона карты > 384 (назвать фактическое
   число), длина base64 ≤ 150 000, число картинок ≤ 2, а для иллюстрации
   по-прежнему ≤384.
2. Батч смежных: `test_analysis*, test_module_media_extraction, test_adventure_engine` → 0 failed.
3. Живой замер без модели: собрать запрос для карты из `runtime/books/`
   (рендер коробки), напечатать `px`, `len(url)`, `картинок`. Денег не тратить —
   модель не вызывать.
