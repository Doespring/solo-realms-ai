# r149 — Мир из PDF доезжает до игры, а не теряется после редактора героя

## ЦЕЛЬ

После цепочки «PDF → редактор персонажа → игра» кампания должна быть привязана к
модулю, разобранному из книги, и первый ход должен идти по её сцене. Сейчас связка
обрывается: разобранный материал сохраняется в черновик подготовки, а кампания
создаётся без него.

## ЧТО ПРОВЕРЕНО ПРОРАБОМ

- `web/play.js`, обработчик `toHero()`: после разбора пишет игроку
  «Мир из этого материала подключим отдельным шагом» — **этого шага нет**.
- `web/preparation.js` умеет привязывать сборник и модуль к черновику
  (`draft.body.adventure_bundle`, `draft.body.adventure_module`) — но только в
  экране подготовки, не в чат-диалоге «Начать приключение».
- `web/creation.js`, `web/prototype.js` читают `draft.adventure` / `world_run_id`
  для подготовленного мира, поэтому привязка технически поддержана на уровне контракта.
- Живой ход с моделью на текущем HEAD работает (r144): модель → команда → движок →
  бросок → журнал → текст Мастера, ~0,04–0,05 ₽ за ход.

## ЧТО СДЕЛАТЬ

1. Сохранить в черновике подготовки ссылку на сборник и модуль из библиотеки
   (после автонарезки r148), не теряя её при переходе на шаг «Соберите героя».
2. При создании кампании из редактора героя — передать эту привязку; если мир не готов
   (`world-readiness`), честно сказать игроку, что кампания начнётся без книги, а не
   молча подсунуть пустой мир.
3. Сделать сквозной прогон «книга → герой → 3 хода» и записать его результат числами.

## НЕ ТРОГАТЬ

- `vendor/nat20/**`, `PATCHES.json`.
- Правила в JS: сцена и механика приходят с сервера.
- Файлы CRLF — править байтами.
