# r155 — подтверждённая карта раскрывается репликой игрока на живой кампании

## ЦЕЛЬ

Подтверждённый материал (карта/раздатка, `status='confirmed'`) попадает на
экран «Раздатки и карты» и в `known_media` кампании **по ходу игрока**, а не
только тестом. Сейчас в r151 записано: «автоматического раскрытия всех
подтверждённых карт при старте кампании нет (это решение Мастера, и тест
`test_adventure_engine` держит `known_media` пустым до события)».

## ЦЕЛЬ В ОДНОМ ХОДЕ

Игрок пишет «Показываю игрокам карту лагеря» / «Раздаю письмо» → кампания
находит подтверждённый материал книги по напечатанному названию (или по
странице, названной в реплике) → создаёт событие `handout` → материал виден в
экране «Раздатки и карты» и в `known_media`, а ход отвечает игроку понятным
текстом («Карта лагеря на столе, стр. 19»).

## ФАЙЛЫ

- `solo/adventure_library.py` / `solo/module_media.py` — поиск подтверждённого
  материала по имени и странице (только чтение существующей опечатки `media_index`)
- `solo/game_commands.py` или место, где распознаются команды хоста
- `solo/nat20_screen.py` — согласовать список доступных действий экрана
- `web/adventure.js` — только если экран не обновляется после события
- тест: `tests/test_confirmed_map_on_a_turn.py`

## НЕ ТРОГАТЬ

- `vendor/nat20/**`, `PATCHES.json`.
- Правило «материал без подтверждения и `sanitized` в игру не идёт» — не ослаблять.
- `tests/test_adventure_engine.py` (держит `known_media` пустым до события) — не
  переписывать, добавить свой тест.
- Лимит зрения модели (≤384 px, ≤2 картинки на запрос) — не трогать.

## ЧТО СЧИТАЕТСЯ ОТКАЗОМ (честные границы, их назвать в отчёте)

- Реплика без названия материала и без страницы — не угадывать: ответ
  «В кампании нет подтверждённой карты с таким названием; вот что есть: …».
- Материал `status='candidate'` — не раскрывать, отвечать, что он ждёт
  подтверждения человеком.

## ПРИЁМКА (вывод в отчёт)

1. `SOLO_TEST=1 .venv/bin/python -m pytest tests/test_confirmed_map_on_a_turn.py -q` → N passed.
2. Батч смежных: `test_adventure_engine, test_module_media_extraction,
   test_module_scene_from_book, test_pdf_world_reaches_campaign` → 0 failed.
3. Живой прогон по HTTP (свой порт, `runtime/r155-live*`, офлайн-мок):
   книга с картой (`runtime/books/The Rise of Tiamat RUS.pdf` или
   `Тёмный учитель.pdf`) → импорт → `PUT /api/adventure/review/materials/{id}`
   подтвердить карту → кампания из книги → ход «Показываю игрокам карту …».
   В отчёте: id материала, `status`, событие `handout` (тип и payload),
   `known_media` до и после, ответ игроку дословно.
4. Тот же ход на материале `status='candidate'` → отказ с причиной.

## ОТЧЁТ (15 строк max)

Коммит `r155: <что>`. Как ищется материал, что происходит при неоднозначности,
числа приёмки. Плохое — первой строкой.

## ПОТОЛОК

Два подхода. Не закрылось — отчёт фактами, карточку не закрывать.
