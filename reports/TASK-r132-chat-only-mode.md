## 0. Что уже проверено (не перепроверять заново)

1. `/` отдаёт `web/index.html` (`solo/app.py:129`); при `experimental=True`
   сервер вставляет notice после `<body>`. Значит HTML уже проходит через
   серверную обработку — фильтровать скрипты можно там же.
2. В `index.html` **8 видов**: `play, journal, campaigns, saves, master,
   performance, cloud, costs`, переключение — кнопками `[data-view]`.
3. Внутри `#play` уже минимально: `#chat`, `#action-form`, `#player-input`,
   `#send`, `#stop`, `#begin`, `#story-status`, `#scene-risk` — ровно три
   кнопки (начать, отправить, остановить стрим).
4. **Панели создаются JS-модулями, а не разметкой.** `web/inventory.js`,
   `tabletop.js`, `game-screen.js`, `prototype.js`, `prototype-actions.js`,
   `workspace.js`, `chronicle.js`, `adventure.js`, `navigation.js`,
   `wizard.js`, `creation.js`, `preparation.js`, `rulesets.js`, `world.js`,
   `obsidian.js`, `desktop.js` — каждый строит свой `section.view` и
   вставляет его в DOM. Не подключили скрипт → панели нет вовсе.
5. Поэтому правильный способ — **серверный фильтр списка `<script src>`**, а
   не `display:none`: скрытая кнопка остаётся в DOM, её видит скринридер и по
   ней можно случайно кликнуть.

## 1. ЦЕЛЬ

Страница `/?ui=chat` отдаётся как один экран: лента игры + поле ввода +
«Отправить». Ни навигации, ни панелей персонажа/инвентаря/карты/боя/мастера/
бюджета — их скрипты не подключены и их элементов нет в DOM. Прежний `/`
работает как раньше.

1. **Определи минимальный набор скриптов, без которых путь не работает.**
   Точно нужен `play.js` (лента, отправка, стрим). Проверь исполнением, нужны
