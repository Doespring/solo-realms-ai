# r164 — браузерная приёмка сквозного пути: книга → модуль → герой → кампания → ход

## ЦЕЛЬ

Доказать в настоящем Chromium, что владелец завтра сможет пройти путь целиком
мышью, а не curl'ом: открыть приложение → «Начать приключение» → загрузить книгу
`Hoard of the Dragon Queen RUS.pdf` (8,9 МБ, то есть ветка библиотеки, а не чата)
→ получить модули → выбрать модуль → сделать героя → начать кампанию → отправить
ход → увидеть ответ и карту. И починить найденные разрывы клиента.

## ЧТО УЖЕ ПРОВЕРЕНО ПРОРАБОМ (не перевыводить)

- Серверный путь целиком проходит по HTTP на коммите `d2eb422` и новее: режим
  ревью 200 → импорт через библиотеку 107/107, 8 модулей `ready` → кампания
  Nat20 200 → `attach` модуля 200 → подтверждение карты 200 → ход «Показываю
  игрокам карту …» → `resolved`, текст «…на столе, стр. 19», картинка игроку
  200, 2047×1526 → механический ход 200 → `play` 409 (так и надо).
- Все нужные маршруты в клиенте есть: `web/adventure.js` (ревью-сессия,
  attach/continue, library, материалы), `web/preparation.js` (черновик и загрузка
  файла), `web/game-screen.js` и `web/play.js` (`command-turn`, `nat20/campaigns`),
  `web/wizard.js` (выбор подкласса, включая PHB-коллегии после r147).
- Значит задача не «написать путь», а «доказать, что мышью он не рвётся, и
  починить то, что рвётся».

## ЧТО СДЕЛАТЬ

1. Поднять приложение **на офлайн-моке** (свой порт, чистый `runtime/r164-live`,
   0 платных вызовов).
2. Пройти мышью в Chromium весь путь из ЦЕЛИ, на каждом шаге фиксируя:
   URL, видимые кнопки, что нажал, что появилось, `consoleErrors`.
   Готовый зонд — `solo-realms-coding/scripts/browser_chat_probe.py`; для шагов
   загрузки файла и выбора модуля дописать шаги, а не подменять их curl'ом.
3. Успех шага — видимый результат на экране, а не код 200 в сети. Пустая лента,
   «ничего не произошло», кнопка без обработчика — провал шага.
4. **Чинить только то, что ломает путь** (не больше трёх правок): клиентская
   ошибка, неверный маршрут, панель без данных. Косметика — в комментарий
   следующей карточки, не в код.
5. Если шаг упирается в серверный дефект вне клиента — не править `solo/`
   вслепую: описать точный запрос/ответ и завести комментарий с доказательством.

2. Скриншоты трёх ключевых экранов: модули книги, герой выбранного класса,
