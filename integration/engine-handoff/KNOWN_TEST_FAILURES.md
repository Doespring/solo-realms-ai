# Известные провалы тестов и их причины

Справка к `DELIVERY.md` (14.135-14.191).

> **Поправка раунда 102.** Утверждение «ни один провал не относится к механике
> движка» было **неверным**: `test_nat20_rage.py` падал именно по механике —
> `_formula_carriers` клал ключи `@scale.*` с префиксом, а `_resolve_token`
> ищет голый ключ, поэтому Rage и Sneak Attack бросали
> `ValueError: Unresolved @scale token`. Исправлено (`7f3ef5d`), rage 2 passed.
> Провалы `bless`/`new_process` остаются и объясняются ниже.

**Две процедуры дают разные числа — это разные измерения, не противоречие:**

| Процедура | Файлов | Результат | Где |
|---|---|---|---|
| общий прогон | 32 | `11 failed, 285 passed` | 14.135 |
| пофайловый прогон | 31 | `10 failed, 280 passed` | 14.189 |

Почему расходятся:

- **`test_nat20_playable_rules.py` падает только в общем прогоне.** Он не «проваливается», а не может
  выполниться: подпроцесс с `cwd=PROJECT` ждёт `rules_data`, которого в этой папке нет (14.181),
  до `timeout=150`. В пофайловом прогоне файл исключён.
- **Пофайловый режим не воспроизводит совместное исполнение.** Провал, зависящий от общего
  `_LIB_LOADER`, при отдельном запуске может не проявиться: нет соседа, который испортил бы состояние.

Оба числа верны для своей процедуры. Для приёмки сверять надо с той, которой пользовались.

## Причина 1: нарушение очереди хода (8 провалов)

**Что происходит.** Тест вызывает `advance_monster_turn(handle)`, пока ход у персонажа.
Движок отказывает (`orchestrator.py:13647-13652`):

```
IntentRejectedError: not_actor_turn: current_turn='hero' is a Character, not a monster
```

**Отказ верный.** `advance_monster_turn` — ход монстра. Ход МЕЖДУ акторами передаётся только
явной командой `end_turn` (`PlayerIntent(intent_type='pass')`), затем прогоняется ход монстра
(`solo/nat20_worker.py:122-130`).

**Правильный порядок** (проверен исполнением, 14.141):

```python
await submit_player_intent(handle, 'hero', PlayerIntent(intent_type='pass'))
await advance_monster_turn(handle)
```

Результат на реальном бою (герой 12 HP / AC 18 против гоблина 7 HP / AC 15):

```
ход после старта: hero
БЕЗ pass: IntentRejectedError | not_actor_turn: current_turn='hero' ...
С pass:    OK, ход у hero, HP: {'hero': 12, 'goblin': 7}
```

**Правка не требует изменения движка** — только порядка вызовов.

**Родственные формы провала** — то же ожидание «действие передаёт ход», записанное через другие
поля:

| Файл:строка | Поле | Ожидалось |
|---|---|---|
| `test_nat20_api.py:100` | `current_turn_index` | `1` |
| `test_nat20_command_cycle.py:105` | `combat.turn` | `'goblin'` |
| `test_nat20_screen.py:95` | `combat.current_actor` | `'goblin'` |

**Решение:** привести тесты к контракту (добавить `pass` перед `advance_monster_turn`) ИЛИ
добавить автопереход в хост. Выбор — за владельцем потока приложения: оба варианта меняют
`solo/`, который этой папке не принадлежит.

## Причина 2: устаревший снимок боя (2 провала)

**Что происходит.**

```
ValueError: Nat20 initial replay diverged
```

Источник `solo/nat20_worker.py:82-92`: `replay(combat)` заново вызывает `start_combat(...)` и
сверяет `digest({'snapshot': read_combat(handle), 'events': events}) != combat['initial_digest']`.
Восстановление отклоняется, если механика изменилась с момента записи.

**Это защита, а не дефект.** Снимок `9723a04 Snapshot before D&D 2024 engine redesign` старше
текущего движка; его отпечаток не совпадает. Ослабление `replay` вернуло бы в игру
невоспроизводимые бои.

**Решение:** перезаписать фикстуру. Новые бои сохраняются и восстанавливаются корректно
(14.119, `test_replay_verify_matches_mid_combat`).

**Для интегратора важно:** при переносе движка существующие боевые сохранения игроков дадут
тот же отказ. Нужна МИГРАЦИЯ сохранений, а не откат движка.
