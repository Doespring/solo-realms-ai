## Что изменилось в раундах 18–28

1. **`rules_edition: str = "5.2"`** добавлено в `CharacterBuildSpec` и `DerivedSheet`
   (`build_spec.py`). Сохранения, записанные до появления поля, читаются без миграции.
   Умолчание `5.2` — единственная редакция корпуса.
2. **Скрытая атака** переведена с проверки данных на проверку боя: мутация обработчика
   теперь даёт отказ (`test_nat20_sneak_execution.py`).
3. **Четыре находки независимого критика** об исправленных проверках-тавтологиях закрыты;
   каждая подтверждена мутацией.
4. **Шов `configure_lib_loader`** проверяется поведением: подменённая запись обязана
   измениться в глазах движка, остальной корпус — нет.

## Порядок подключения

```python
# SRD-режим (по умолчанию): ничего подключать не нужно.
from dnd5e_srd_data.loader import BundledAssetLoader

# PHB-пакет: явное подключение отдельным загрузчиком.
from dnd5e_engine.lib_loader import configure_lib_loader
configure_lib_loader(MyPackLoader(base=BundledAssetLoader()))  # свой источник
configure_lib_loader(None)                                     # снять
```

PHB не включается автоматически: в `vendor/nat20/packages` ровно два пакета
(движок и SRD-данные). Отсутствующая запись возвращает `None`, а не похожую:
движок не подставляет догадку.

## Совместимость сохранений

- Персонаж без `rules_edition` считается записанным по SRD 5.2.
- Изменение схемы не требует миграции: поле имеет умолчание и не влияет на расчёт.
- Отказ вместо угадывания: при неизвестной редакции проверка корпуса сообщает ошибку,
  а не подменяет правила.

## Реальные ограничения

1. **Подклассы:** корпус SRD 5.2 содержит по одному на класс (12), полная книга даёт ~48.
   Механика разбора, выбора, уровней и доменных заклинаний реализована и проверена.
2. **Заклинания:** 339 записей, из них 121 отвергнута генератором корпуса.
3. **`rules_data`** отсутствует в этой ветке — 89 гибридных проверок недоступны,
   включая Bless. Подмена догадкой запрещена п.2.
4. **Препятствие интегратора:** `solo/nat20_prototype.py` строит ожидаемый набор только
   из `UPSTREAM.json` и не применяет `PATCHES.json`, поэтому отвергает собственный
   корпус (`spells/fireball.json`). Спецификация исправления:
   `integration/engine-handoff/HOST_PATCH_CORPUS_PIN.md`.
