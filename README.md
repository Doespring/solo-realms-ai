- `data/` — существующие данные; при очистке их не удаляли и не мигрировали.
- `build-tools/` — сохранённые инструменты упаковки.
- `dist/pdf-playable/SoloRealmsAI-Prototype/` — единственная оставленная готовая
  Windows-поставка .5. Она старее последующих source-изменений этапов1–3.
- `docs/MASTER_SPECIFICATION-4.1.md` — собранное входное ТЗ4.1; наличие документа
  не означает выполнения всех его требований.
- `reports/` — краткие актуальные итоги, контрольные суммы и отчёт очистки.

## Запуск, когда владелец решит продолжить

Из исходников: `Desktop.cmd` или явный offline `Prototype-Offline.cmd`.
`Start.cmd` вызывает `Web.cmd` и запускает текущую веб-версию. `Desktop.cmd`
остаётся отдельным запускателем desktop-режима. Для браузера из корня вручную:

`Web.cmd` использует отдельный локальный профиль `runtime/web-local` (исключён
из Git), чтобы не требовать записи в AppData. Это новый профиль, без переноса
старых кампаний и настроек; прежние профили остаются на месте. Другой профиль
можно явно выбрать переменной `SOLO_WEB_DATA_DIR` перед запуском `Web.cmd`.
Облачный профиль при необходимости нужно настроить в интерфейсе заново.

```powershell
$env:SOLO_DATA_DIR=Join-Path (Get-Location) 'runtime/web-local'
.venv/Scripts/python.exe -X utf8 -B scripts/start_cloud.py --data-dir "$env:SOLO_DATA_DIR" --port 19215 --open
```

Готовый отдельный EXE: `dist/pdf-playable/SoloRealmsAI-Prototype/SoloRealmsAI.exe`.
Не отделять его от `_internal`. Запуск приложения сам по себе не выполняет AI-запрос.
Для облачной игры пользователь настраивает собственный профиль/ключ.

ограничены. Свежий каталог~0.70с, сохранённый~0.43с; полное окно<500мс не подтверждено.
