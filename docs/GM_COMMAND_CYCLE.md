# Воспроизводимый цикл мастера: намерение → движок → рассказ

Рабочий срез на 17 октября 2026: исследовательская проверка → базовый бой → отдых.
Запускается без настроек провайдера, ключей и платных вызовов.

Backend выбирается единообразно через `solo.command_backend`: наличие `state.nat20`
направляет команды и снимки в Nat20GameEngine; остальные кампании используют прежний
CommandEngine. Interpreter и проверенный Narrator сохраняются. Nat20 использует
тот же GameCommand, GameEvent, GameSnapshot, журнал и атомарную проекцию памяти.
Старый versioned envelope Nat20 читается при повторе без повторного исполнения.
Проверенный каталог Nat20 содержит athletics/perception/strength и один basic combat;
это отдельный ограниченный профиль, а не перенос всех правил или изменение UI.

Из корня проекта:

```powershell
.venv/Scripts/python.exe -m scripts.command_smoke --output reports/command-cycle.json
.venv/Scripts/python.exe -m pytest -q -p no:cacheprovider tests/test_command_cycle.py
```

`reports/command-cycle.json` — восемь ходов: исходное намерение, версия до/после,
строгий GameCommand, GameEvent с типизированными эффектами, видимый GameSnapshot,
итоговый рассказ и способ его проверки. Случайные ID кампании/журнала нормализованы;
два независимых запуска дают одинаковый JSON. SQLite демонстрации создаётся во
временном каталоге и удаляется после запуска. Пользовательские кампании не нужны.

Демонстрационный герой с силой 30 — тестовая фикстура для короткого боя. Формулы
проверки, инициативы, попадания, урона, расхода действий и восстановления выполняет
существующий Python-код. Заранее заданные значения RNG: `13, 18, 4, 15, 3, 15, 4`.
Хиты героя: `14 → 9` после ответа NPC, `9 → 15` после короткого отдыха,
`15 → 20` после длительного. Ресурсы восстанавливаются согласно их recovery.

## Переиспользованные компоненты

- `Game.play_command` — новый метод существующего оркестратора `Game`, с его
  блокировкой операции и модельным scope. Повтор request_id возвращает сохранённый
  результат без новых бросков и генераций. Отменённый запрос не исполняется снова.
- `ModelBehaviour.interpret_command` — существующий Interpreter transport,
  `mode=interpreter`, JSON schema и валидация Pydantic. Существующий профиль
  Interpreter не заменяется новым провайдером. Контракт `gm_commands_v1` явно
  выбирается в прежнем `CloudLLM`, чтобы старый промпт IntentPacket не конфликтовал
  с CommandIntent; wire-запрос проверяется через `httpx.MockTransport`.
- `SceneCompiler.command_context` / `engine_context` → `EngineMemoryAdapter.context`
  — Memory Context Builder с прежним retrieve, ACL, ограничением истории и бюджетом.
  Python передаёт актуальный снимок, в том числе до первого события. Прежние
  `scene`, общая история и литературный текст источниками контекста не являются.
- `ModelBehaviour.narrate_scene`, `StreamPresentation`, `narrative_grounding`
  — прежний Narrator и его проверка представления. Ответ буферизуется; новые
  факты, предложения и неподтверждённые действия заменяются детерминированным
  рассказом по подтверждённому исходу. Ошибка рассказчика не повторяет механику.
- `CommandEngine` — адаптер команд/DTO, без новой реализации правил.
  `RulesetEngine.check/rest` разрешают проверки и отдых. Бой использует вынесенные
  без изменения вычислений `CombatService.start_transition/execute_transition`
  и прежнюю политику NPC. Старые боевые API вызывают те же переходы.
- `Store.engine_event` и `Memory.ingest` — прежняя атомарная транзакция и хранилище.
  GameCommand, GameEvent и GameSnapshot хранятся вместе в scripted result;
  `state.engine_snapshot` обновляется в той же транзакции. Проза сохраняется
  отдельно через существующий `Store.narrative` и никогда не становится командой.

`solo/gm.py` обслуживает отдельные внеигровые вопросы о правилах. Для игровых
команд не создаётся второй GM или альтернативный решатель механики.

## Закрытый контракт сегодняшних инструментов

`solo/game_commands.py:tool_schemas()` возвращает function schemas с `strict=true`,
обязательными полями и `additionalProperties=false`, включая вложенную позицию.
Они объявляются существующему Interpreter вместе с грамматикой `CommandIntent`.
Используется прежний structured JSON transport; новый клиент native tool calling
не добавлен. Диспетчер принимает только валидированный GameCommand.

| Команда | Аргументы AI | Решение Python |
| --- | --- | --- |
| check | check_id | Только зарегистрированная проверка текущей локации; характеристика, Сл, владение и бонусы из сценария/листа |
| start_combat | encounter_id=basic | Существующее базовое столкновение, карта и снаряжение героя |
| move | position: x, y, z | Геометрия, дистанция, занятые клетки, реакции, остаток движения |
| attack | target | Видимость, допустимость цели, действие, попадание и урон |
| end_turn | нет | Инициатива, автоматические ходы NPC по существующей политике, возврат хода герою |
| short_rest | hit_dice | Доступность отдыха/костей, броски восстановления и ресурсы |
| long_rest | food_water | Временные ограничения, восстановление и ресурсы |
| end_combat | нет | Только разрешённый бой без живых врагов и ожидающих последствий |

Координаты этого контракта начинаются с нуля. request_id и expected_version
подставляет оркестратор, AI их не назначает. Инструменты не принимают Сл, урон,
броски, правила, произвольные эффекты, таблицу противников или патч состояния.

Один успешный GameEvent `command_resolved` содержит исход и список строгих эффектов
`roll/damage/healing/resource/condition/movement/combat_started/combat_ended`.
Эффекты изменений показывают итоговые before/after команды, а не каждую клетку
пройденного пути. Проверка и атака/инициатива содержат броски движка. Память получает
типизированные эффекты; литературный outcome не извлекается как факт.

## Вход и отказы

```http
POST /api/campaigns/{campaign}/command-turn
Content-Type: application/json

{"request_id":"turn-1","text":"Исследую следы","expected_version":0}
```

Существующий `Game.play_command(campaign, request_id, text, expected_version)`
доступен и напрямую. Прежний `/play` и экран не переключены автоматически;
этот отдельный вход позволяет проверять ограниченный срез без переделки дизайна.
Существующая сборка EXE не пересобиралась.

- `clarification`: неоднозначность, несколько действий, отсутствующая цель или
  невалидный ответ Interpreter. Возвращается вопрос; движок не вызывается.
  Вопрос сохраняется через существующий `Store.converse`; ответ игрока объединяется
  с прежним намерением во входе Interpreter, включая после перезапуска. Это диалоговый
  ввод, а не новый источник фактов о мире. При смене версии старое намерение не исполняется.
- `unsupported`: Interpreter сообщает ограничение; механического успеха нет.
- `rejected`: Python отклонил нелегальную/неизвестную команду. Транзакция откатывается.
- `state_version_error`: проверка перед интерпретацией и повторно внутри write
  transaction. Возвращается обновлённый видимый снимок и `state_version`; автоматического исполнения
  по новой версии нет.
- `ai_error`: Interpreter недоступен; команда не выполнена.
- `resolved`: движок подтвердил результат; даже при ошибке Narrator доступен
  проверенный рассказ. `engine_fallback` явно отличим от `engine_verified`.

Полный внутренний снимок не отправляется AI или в этот API. Каждое поле проходит
scope/known_by; Narrator не получает private-ресурсы чужих акторов, secret/gm или
произвольную прозу из истории. Отдельный NPC-диалог в этот срез не входит.

Ограничения среза: один basic encounter и одна команда на реплику; проверки Solo должны
быть зарегистрированы в `locations[].checks`, а Nat20 — в закреплённом CHECKS; произвольное исследовательское
перемещение, заклинания и реакции как инструменты пока отсутствуют. Ожидающую
реакцию/необратимый исход движок останавливает и объясняет. Сценарии adventure и
отложенные world.events честно отклоняются: их дополнительные переходы требуют
отдельного согласования снимка после сценарного разрешения.

## Проверки

`tests/test_command_cycle.py` проверяет весь offline-сценарий дважды с одинаковым
журналом, строгие схемы, неоднозначность, неизвестную/нелегальную команду, запрет
механических полей AI, конфликт версии во время Interpreter, отсутствие изменений
при отказах, атомарный откат при сбое памяти, перезапуск/undo/новую ветку, повтор
запроса, изоляцию контекста, выдумку/сбой Narrator и HTTP-вход.

`tests/test_nat20_command_cycle.py` проверяет настоящий Nat20 через тот же HTTP-вход
с mock AI, save → новый процесс → продолжение боя/отдых, память, ACL, повтор,
устаревшую версию до/после Interpreter и откат при отказе Memory. Raw native state,
seed и события backend не отправляются мастеру или в публичную историю.
