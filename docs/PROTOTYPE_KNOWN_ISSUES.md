# Experimental prototype — known issues

Version 2.2.0-prototype.5 (Native action parameters and isolated PDF session QA). Current UI/GM/Rules/Memory source deliveries integrated;
common offline regression and native packaged acceptance are recorded separately in
reports/pdf-playable-release/RELEASE.md. Source browser checks
are not evidence of a frozen Windows EXE launch.

- One pinned Nat20 0.7.0, no runtime fork. Full catalog coverage is not full D&D automation.
- Bless is blocked because pinned upstream concentration/save/recast are incorrect;
  Hide is blocked because it fails to spend Action. These local refusals do not disable classes.
- New encounters derive representable NPC attack modifiers from public Native stat-block
  operations; Wolf/Rat/Goblin were checked. Different modifiers across actions and other
  unrepresentable profiles remain unbound, with a specific refusal for that attack.
  Explicit authored overrides need their source; existing saves are not rewritten.
- Rage activation is blocked because the pinned Native effect is disabled; other Barbarian
  actions remain available. Native damage/riders still have upstream approximation limits.
- Magic outside combat/rituals, complete VSM/free-hand accounting, all prerequisites and
  counts for prepared spells/class choices are incomplete. UI builder is single-class.
- Full death procedure at 0 HP is not implemented: supported scenario stops, allows restore;
  it does not declare final death. Mixed hit-dice/time-effect rest restrictions remain.
- Author encounter template currently supports four selected enemies; backend supports more.
  Selected native action parameters now have schema-based UI controls (charges/direction/pool);
  this does not certify every operation or resource combination. Trading/quantity management
  is not declared complete. Native names are partly English; long forms require scrolling.
- Preparation requires a supported, source-confirmed structured world or explicit sandbox.
  Arbitrary PDF automation and all book mechanics are not claimed. The positive source/browser
  path uses an actual synthetic PDF with offline MockTransport, not live AI or a user's book.
  Resume mode/edition come from the server even after empty browser storage; unknown mode
  requires an explicit choice. Frozen synthetic-PDF API checks are reported separately from
  source/browser UI acceptance; user books and live provider results remain unverified.
- Live provider compatibility, reasoning, cloud latency/cost and literary quality are untested.
  Cloud mode starts unconfigured, with no inference on startup; no keys are bundled/copied.
  Offline-Mock is separately labelled and uses a separate default profile.
- UI labels/creation attack-source binding and scoped NPC-topic fallback defects are resolved;
  their earlier failing QA evidence remains for provenance, not as current open blockers.
- Portable needs Windows 10 19041+/11, WebView2 and .NET; no installer or signing here.
- Historical data-preservation incident remains OPEN in
  reports/preview10/DATA_PRESERVATION_INCIDENT.md. Only fresh explicit profiles are tested.
  Functional integration does not resolve that incident; project data/ is protected.

Cleanup: previous TEMP directory removal was rejected as blocked by policy. No workaround
or repeat is attempted. Current owner QA evidence is retained through the common gate.

PDF hotfix: exact known [S001] reference wrappers and a narrow known missing-array delimiter
can be repaired locally from saved responses. Five actual saved responses parsed read-only;
the empty failed block still needs a new response. No live profile was resumed or changed.

The structural world path can preserve a D&D2014 source and explicitly confirm D&D2024

Names-only caches require a separately consented structural run; no automatic edition/engine change.
