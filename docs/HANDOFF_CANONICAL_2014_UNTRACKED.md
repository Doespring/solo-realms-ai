# Находка: незакоммиченный каталог `canonical_2014` вне учёта

Дата: 27 октября 2026. Статус: **чужое незавершённое изменение, не тронуто**.

## Что обнаружено

В `vendor/nat20/packages/dnd5e-srd-data/src/dnd5e_srd_data/canonical_2014/` лежит каталог SRD 5.1
(2014) — 848 файлов, из них 800 заклинаний и 48 подклассов. Он **не закоммичен** (`git status` → `??`).

| Что | Значение |
|---|---|
| Записей в `UPSTREAM.json` с `canonical_2014` | **0** |
| Записей в `PATCHES.json` | **0** |
| Записей в `manifest.json` релиза | **0** (там 1664 файла, все из `canonical/`) |
| Проверяется `verify_tree` | **нет** |

Значит 848 файлов не покрыты ни пином, ни реестром патчей, ни манифестом: их изменчивость
целостностью не контролируется, а отпечаток релиза от них не зависит.

## Игровое последствие — подтверждено

`BundledAssetLoader` сознательно ищет в 2024 и откатывается в 2014 (`loader.py`, `_legacy_category_dir`).
Так как фильтр `subclass_options` (`rules/advancement.py:714-717`) не различает издание,
матч по `class_identifier` даёт смесь изданий:

```
subclass_options('fighter', 3) -> ['battle-master', 'eldritch-knight', 'psi-warrior', 'champion']
subclass_options('wizard',  3) -> ['school-of-evocation', 'evoker', 'school-of-illusion',
                                   'school-of-abjuration', 'school-of-divination']
```

Из 12 подклассов 2024 в каталоге только `champion` для воина и `evoker` для волшебника;
остальные приходят из 2014. Для волшебника в списке одновременно `evoker` (2024) и
`school-of-evocation` (2014) — это одно и то же по смыслу, но две разные записи и два разных слага.

## Почему не исправлено здесь

- `canonical_2014` — чужое незакоммиченное изменение, его нельзя ни удалять, ни переписывать.
- Разделение изданий — архитектурное решение потока движка, а не host-адаптера.
- Правка фильтра в `rules/advancement.py` меняет поведение движка и требует согласованной передачи.

## Передача потоку движка

1. Каталог `canonical_2014` вне пина/патчей/манифеста — решите, он часть поставки или временный.
   Пока он вне учёта, `verify_tree` его не защищает, и отпечаток о нём не знает.
2. Решите, должен ли `subclass_options` различать издание. Сейчас выдаётся смесь 2014+2024,
   и одинаковые по смыслу записи (`evoker` / `school-of-evocation`) сосуществуют.
3. Касание правки: `solo/nat20_boundaries` не затронут, изменений в движке я не делал.

## Что проверено и цело

Корпус 2024 не испорчен: **1664 из 1664** файлов `canonical/` совпадают по SHA-256 с `manifest.json`
релиза `prototype-srd-2024-v1`. Ни одного расхождения, ни одного отсутствующего файла.
