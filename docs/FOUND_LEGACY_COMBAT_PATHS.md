# Найдено критиком: legacy-бой доступен в обход Nat20

Дата: 27 октября 2026. Статус: **найдено, не исправлено** (вне узкого скоупа текущего задания).

## Что найдено

Запрет в `solo/command_engine.py::resolve()` закрывает только путь командного цикла.
Остались живые пути, которые запускают Python-бой, **не проверяя** наличие `state['nat20']`:

| Файл:строка | Что делает |
|---|---|
| `solo/game.py:910-917` | фраза «подтверждаю столкновение» → `CombatService.start(...)` |
| `solo/game.py:940-959` | текстовые команды боя → `combat_api.text_command` / `plan_command` |
| `solo/combat_api.py:51-70` | `POST /api/campaigns/{c}/combat/start` и `/combat/command` |
| `solo/play_screen.py:41,204,206` | экран игры вызывает тот же legacy-слой |
| `solo/combat_service.py:106,148` | `start_transition` / `execute_transition` гоняют `CombatEngine`
  на зашитой карте 12x10 с `foe-1` |

**Проверено критиком:** при подмене `native_backend` все 5 боевых команд уходят в Nat20 (`command_engine.py:165-169`),
но перечисленные пути идут мимо `command_engine` и `native_backend` вообще.

## Почему не исправлено сейчас

- Узкий скоуп задания — достоверная проверка работающего движка, а не закрытие всех legacy-путей.
- Эти пути используются интерфейсом (`play_screen.py`), и их закрытие требует UI-проверки,
  которая в этой среде невозможна: `browserType.launch: spawn EPERM`.
- Закрыть их вслепую — значит с высокой вероятностью сломать работу, не имея возможности проверить.

## Что нужно сделать

1. Решить, поддерживаются ли вообще кампании без Nat20 в боевой части.
   Если нет — все перечисленные входы должны отвечать отказом, а не запускать `CombatEngine`.
2. Проверить закрытие на живом интерфейсе (браузер обязателен).
3. Пока это не сделано, нельзя утверждать, что legacy-бой полностью недоступен.
