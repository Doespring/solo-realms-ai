# Рывок: минимальный production-пакет

Дата: 2026-10-18. Поддержанный персонаж — существующий человек-воин первого
уровня, включая `fighter-standard-array-2024-v1` (обычные HP 12, AC 18).
Редакция `dnd2024`. Исходники и установленный Nat20 0.7.0 не изменены;
commit `e187c813bb4e43c4e4e62942ecd83831f1cdbcaa`, content release
`374afd1a3898e089e023130cc342a0f3c6fe88a75bf4f8ee7e3bf865852abf75` прежний.

## Реальное подключение

Публичный `submit_player_intent(handle, 'hero', PlayerIntent(intent_type='dash'))`
уже поддерживается upstream. `_handle_dash` в закреплённом Nat20 расходует
Action, добавляет эффективную скорость и оставляет текущий ход герою.
Движение, ограничения и сброс бюджета на новом ходу исполняются Nat20.
В Solo добавлено только отображение закрытой команды на этот intent.
Upstream `IntentRejectedError` преобразуется в штатный отказ адаптера, в том
числе для disposable-проверки доступности. Формул движения в Solo не добавлено.

Путь: общий `GameCommand` → существующий выбор backend → Nat20 worker →
общие `GameEvent/GameSnapshot` → одна транзакция состояния и памяти.
`/command-turn` принимает предложение mock/AI-Мастера, `/commands` — ту же
типизированную команду. Повтор request ID возвращает сохранённый результат.
Нового журнала, DTO семейства или канала изменения состояния нет.

## Контракт и поля экрана

Единственный новый payload: `{"kind":"dash"}`. Скорость, количество движения,
бонусное действие и патчи состояния задать нельзя. Обновлена существующая
`integration/nat20/schemas/game-command-v1.schema.json`; расширено перечисление
`CommandResolution.command`. Версии конвертов остаются прежними: дополнение
аддитивное, старые команды и записи не преобразуются.

В `commands[]` сервер предлагает `label="Рывок"`, `kind="engine"`,
`parameters={"kind":"dash"}`, текущую `expected_version` и обычный ID команды.
Доступность проверяет реальное исполнение в disposable Nat20 replay.
Подтверждённые `movement_remaining` и `action_available` уже передаются через
`snapshot.hero.resources[]` (`id`, `label`, `current`, `maximum`). Экран не
должен вычислять прибавку движения или законность действия. `web/*` не менялись.

## Проверки

`tests/test_nat20_dash.py`: публичный upstream без математики Solo; движение
до/после Рывка и сверх исходного бюджета; расход Action; отказ повтора/атаки;
сброс на следующем ходу; request idempotence и конфликт версии/ID; откат при
ошибке памяти; HTTP mock AI и серверная доступность; JSON Schema и запрет
лишних полей; старый preview.7 fixture; checkpoint → новый Python-процесс →
точное совпадение событий и состояния продолжения. RNG и HP также входят в
сверяемое состояние. Протоколы прогонов: `reports/nat20-dash/*.xml`.

Целевые регрессии охватывают существующие командный цикл, память, Nat20 API,
типизированный игровой набор (обычный воин → бой → XP → отдых → перезапуск),
серверную проекцию и прежний Solo-экран. Полный набор не запускался.

Результат: **76 уникальных целевых тестов прошли** по последнему результату
каждого теста: `regression.xml` — 72, `movement.xml` — 1, `http.xml` — 1,
ещё 2 неизменённых теста из `tests.xml`. Это объединение целевых прогонов,
а не один общий запуск. Машинный перечень — `reports/nat20-dash/results.json`.
В начальных прогонах исправлены только две ошибки тестового harness: импорт
`StateVersionError` и обращение к вложенному `effect.payload.resource`.
Исходные ошибочные протоколы сохранены для аудита.

## Границы

Рывок доступен только в активном бою на ходу живого героя, если upstream
принимает расход действия. В прежнем Solo backend команда явно отклоняется.
Вне боя, при 0 HP, чужом ходе и после завершения боя прежние ограничения
сохранены. Rogue/Cunning Action, Action Surge, Disengage, условия и новые
персонажи этим пакетом не подключаются. Каталог Foundry и 12 импортированных
документов/provenance не изменены; `capabilities.json` дополняется только `dash`.
Новых данных Foundry и портирования JS здесь нет.

Bless, другие заклинания и Cleric остаются pending; экспериментальные исправления
runtime не используются. Пользовательские кампании не мигрировались и не
изменялись. UI, cloud, PDF pipeline, pins и content hashes не менялись.
