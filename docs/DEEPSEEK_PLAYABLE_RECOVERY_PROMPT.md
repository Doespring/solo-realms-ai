## Границы работы

- Nat20 — единственный калькулятор механики; Solo хранит состояние, транзакции, память/ACL и CostLedger. Никакого нового rule engine, fork, dual runtime или самописной арифметики.
- Hide/Bless и другие известные upstream-дефекты не маскировать снятием guards. Изолированная поломка не закрывает весь класс. Их исправление не должно задерживать рабочий путь остальных доступных действий; фиксируй точные ограничения.
- Сейчас не разрабатывай голос, локальную модель, новую карту, новый инвентарь, дополнительные классы и косметическую перепаковку. ТЗ 4.1 — видение продукта, не приказ реализовать всё сразу.
- Никаких новых EXE/ZIP, публикаций, Google Drive/email и запуска других чатов. Оставленный EXE .5 старее исходников.
- Тесты из .venv, один изолированный синтетический стенд, SOLO_TEST до импорта app. Личные БД/ключи/сохранения не менять.
- Сначала релевантные тесты, затем один общий regression после исправлений и подготовки окружения. Не запускай полный набор снова после каждой мелочи. Если общий прогон непрактичен, укажи конкретную причину и границы проверки.
- Убирай только созданные тобой неактивные временные материалы, после проверки абсолютных путей. Не повторяй и не обходи policy-отказы. Итоговые доказательства и исходники сохранить.
