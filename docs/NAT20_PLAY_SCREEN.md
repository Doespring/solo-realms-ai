# Подключение существующего экрана Solo/Nat20

Игровой экран и его текущая компоновка сохранены. Для явно выбранной кампании Nat20
свободная реплика использует `command-turn`, кнопки — существующий общий `commands`
с `GameCommand`. Оба маршрута выбирают один backend через `command_backend`.
Сохранение и восстановление используют прежние отдельные служебные операции.

`play_screen.screen` получает HP, состояния, ресурсы, порядок/текущий ход и результаты
из серверной проекции Nat20, без `RulesetEngine.sheet` и прежнего CombatEngine.
Типизированные броски читаются из имеющегося журнала, с прежним фильтром адресатов.
Seed, рецепт восстановления, полные native события и личные ресурсы NPC не выдаются.
Счётчик Second Wind отображается как **потрачено**; неизвестный maximum не выдумывается.

`Nat20Screen` проверяет кандидаты кнопок методом `Nat20GameEngine.preview`: общие
preflight-ограничения и штатная механика выполняются в одноразовом локальном worker.
Результаты проб отбрасываются, состояние/журнал/память не записываются. При настоящем
исполнении движок повторяет проверки. Четыре соседние с видимой целью клетки — только
кандидаты перемещения; расстояние, маршрут и законность решает Nat20.
Вычисления/лимиты Nat20 и контракты памяти не изменены.

Кеш ограничен 16 проекциями и включает ID кампании, версию и полный canonical state.
Кандидаты проверяются максимум четырьмя worker одновременно. После undo/restore или
изменения состояния предыдущая доступность не переиспользуется. Первая проекция
новой версии может занимать несколько секунд; UI ждёт её, не отправляя действие
через старый маршрут. Неподдержанный тактический редактор скрыт для Nat20.

Клиент отображает серверные значения и переводы идентификаторов; правил/проверки
законности на клиенте нет. Во время отправки кнопки блокируются. Повтор сохраняет ID,
конфликт обновляет сцену без автоматического исполнения, отказ оставляет ввод игрока.
Рецепт боя проверяется в новом процессе перед первой проекцией после перезапуска.

Целевые проверки: `tests/test_nat20_screen.py`, `tests/test_play_screen.py`,
`tests/test_nat20_api.py` (14 различных тестов). Они покрывают read-only/cache,
конкурентный повтор, конфликт версии, отказ, общий маршрут, ресурс/состояние,
сохранение/восстановление активного боя и обычную Solo-кампанию.
JUnit: `integration/nat20/reports/screen-shared-route.junit.xml` и
`screen-regression.junit.xml`. Ранний `screen.junit.xml` проверяет совместимый вход
до согласования общего маршрута и не прибавляется к числу различных тестов.

Локальный стенд: `.venv/Scripts/python.exe -X utf8 -B scripts/smoke_nat20_screen.py`.
Он использует только mock AI и отдельный `.test-tmp-nat20-screen-smoke`; повторный
запуск читает прежнюю тестовую БД для проверки перезапуска. Production-маршруты,
профиль провайдеров и cloud-бухгалтерия не подменяются. Скриншот восстановленного
хода гоблина: `reports/nat20-screen-restart.png`.

Браузерная проверка 18.10.2026 прошла на реальном локальном HTTP-сервере: после
завершения процесса бой продолжился с HP 7/12 против 6/10, очередью hero/goblin
и ходом гоблина. Бой завершён; короткий отдых дал HP 12/12, hit dice 0 и spent 0.
Две вкладки подтвердили конфликт без повторного действия; обычная Solo-проверка
прошла прежним движком. Устранён старый кеш rulesets.js, вызывавший ошибку листа
после обновления. При смене кампании прежние броски, события и контрольные точки
очищаются до получения новой проекции. Итоговая машинная запись — `reports/screen.json`
в каталоге интеграции; временная диагностика в клиенте удалена.

Границы: прежний поддержанный воин 1-го уровня/гоблин, три проверки, восемь команд;
полный импорт правил, другие действия и карта Nat20 не заявляются. Реальная облачная
модель, EXE и полный набор тестов в эту проверку не входят.
