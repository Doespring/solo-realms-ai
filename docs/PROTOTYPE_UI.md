# Пользовательский интерфейс рабочего прототипа

18.10.2026. **Source UI готов к общему gate. Production-файлы UI заморожены после целевого smoke.** Это результат реальной реализации и проверки с Nat20, не новый frozen EXE и не объявление закрытия инцидента проектных DB. Общий regression/portable собирает интегратор.

## Как начать

Запустить экспериментальный host; для локальной проверки предусмотрен `Prototype-Offline.cmd`. **Новая игра → герой и приключение → Проверить лист → Начать игру**.

На обычном экране доступны класс, вид, подкласс, предыстория, уровень, характеристики, владения/компетентность, классовые опции, экипировка и подготовленные заклинания из настоящего серверного каталога. Native builder проверяет и рассчитывает лист. Песочница и своё описание запускаются напрямую; подтверждённые подготовленные миры выбираются в том же списке. Для них используются уже подтверждённое имя и существующий `launch_prepared` с проверкой revision/согласованности. Импорт материалов и прежний мастер оставлены вторичным путём.

Есть выбор участников возможной встречи, до четырёх в текущем авторском шаблоне. Бой начинается отдельной кнопкой, а не при создании. **Готовый бонус атаки отсутствует в части pinned monster-данных**: обычное раскрытие «Параметры встречи из вашего источника» принимает явное авторское число и источник. Автоматического +0, расчёта по характеристикам или пропуска атаки нет. Без входного значения конкретная атака получает отказ backend. Тестовый Rat использовал явно введённый synthetic authored +0; это не утверждение о вычисленном SRD-stat.

## Игровой экран

- Сохранена прежняя композиция: история, реплика, герой, события, компактный бой, сохранения. Большой список проверок свёрнут в выбор из серверных предложений.
- Подтверждённые HP, ресурсы, ячейки, состояния, инициатива и последний бросок отображаются из snapshot. Лист больше не подписывает любого героя как человека-воина первого уровня. Снаряжение, способности, магия и личные цели показываются по серверным данным; инвентарь Nat20 открыт обычной вкладкой.
- Раскрытие «Оружие, магия, предметы и цели» выбирает операцию, принадлежащий герою предмет/оружие/способность/заклинание, вариант применения, цели и ячейку. Повторные цели допускаются для распределения отдельных эффектов; количество проверяет Nat20. Для движения есть координаты и текущие позиции. Границы ввода берутся из native schema; дальность и законность клиент не рассчитывает. Полноценный новый картографический проект не создавался.
- Обычные предлагаемые кнопки идут из `commands[]`; расширенная форма обозначена как попытка, проверяемая движком. Она отправляет тот же импортированный `NativeAction` через существующий `/commands`, текст — через `/command-turn`. Исправлен pre-engine `KeyError('native_action')` в выборе подписи.
- Отказ отдельной операции оставляет поле и остальные действия доступными. Сохранение/restore остаются служебными операциями. Сохранены clarification, terminal, текстовый draft, чтение без принудительного scroll и возврат к действующей истории после restore.
- Offline test mode подписан явно. Cloud-настройки/лимиты сохранены; отсутствие готового облачного подключения не выдаётся за подключение. Живые или платные вызовы не делались.

Импортируются native build/action типы; второй формат игровых команд, правила и журнал не создавались.

## Проверки

**3 уникальных целевых pytest-теста прошли, без full suite.** Последний реальный UI-прогон — 50,35 с; small-window — 6,51 с; прежний UI follow-up — 6,36 с. Предупреждения только прежние lark deprecation, ошибок JavaScript нет.

1. `tests/test_prototype_ui.py` / `.cjs`: настоящий loopback backend и pinned Nat20, `PreviewMock`, **игровые HTTP-ответы не подменяются**. Через обычный UI созданы Dwarf/Rogue и Dwarf/Wizard. Плут запускает подтверждённый мир из явно размеченного собственного источника, осматривается, проверяет Dex, разговаривает с Дорном, открывает лист/инвентарь, сохраняется и продолжает после reload. Волшебник начинает бой, получает конкретный отказ Hide, затем выбирает Magic Missile и распределение целей: native cast исполнен, ячейка первого круга осталась 1, Rat подтверждён с 0 HP. Аудит памяти: без dangling events/foreign key errors. [Результаты](../reports/prototype-4/results.json).
2. В последнем QA-профиле read-only проверено, что ответ NPC содержит именно знание «Мост закрыт до утра.», а не техническую goals-запись. Это проверка текущего стыка после работы владельца GM, не правка повествования в UI. [Evidence](../reports/prototype-4/social-check.json).
3. `test_small_window_ui.py`: 1280×800 и 960×640, restore/terminal/обычный ввод/черновик/scroll/отменённая ветка/Solo fallback. Здесь игровые ответы — **явные UI-фикстуры**, не новая проверка правил. [Результаты](../reports/prototype-4/small-window/results.json).
4. `test_preview7_ui_followup.py`: 6 прежних browser-сценариев создания, отказов, восстановления и Solo-совместимости. [Результаты](../reports/prototype-4/legacy-ui/results.json).

## Границы следующей приёмки

Полный каталог не означает полную автоматизацию D&D. Native builder сам предупреждает, что не все требования к числу подготовленных заклинаний и классовым выборам полностью проверены. Bless и Hide остаются конкретными известными отказами. Не все расширенные параметры NativeAction получили отдельные удобные controls; простая торговля/управление количеством предметов не выдаются за готовые операции. UI конструктора пока одноклассовый; список подклассов полный, допустимость выбора проверяет builder.

Длинные формы/каталоги требуют прокрутки, часть native названий остаётся английской. Новая форма параметров действия после успешного обновления сцены выбирается заново. Нативный EXE, DPI, платный cloud и общий полный regression здесь не проверялись. Инцидент сохранности проектных данных остаётся отдельным открытым вопросом.

Очистка: собственные test host/browser завершены; исходные `data/`, ключи и incident evidence не затрагивались. По общему протоколу последовательной уборки удаление параллельно Сборке не запускалось. Для её последующей уборки: `reports/prototype-4/tmp`, `tmp2`, `tmp3`, `tmp4`, `tmp5`, `tmp-final`, `tmp-delivery`, `tmp-small`, `tmp-legacy` и исторический `failure.png`; оставить актуальные results/screenshots/social-check и исходники тестов. `tmp-delivery` нужен только до общего gate для воспроизведения, затем также удаляется.
