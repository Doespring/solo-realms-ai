# PDF → подтверждённый мир → Nat20

18 октября 2026. Backend общего пути реализован и проверен локально. Сборка
подключает API, Интерфейс — пользовательский поток. Full/EXE/build не запускались;
живых и платных AI-вызовов — **0**. Рабочие профили, project data/DB/WAL,
сохранённые ZIP и материалы инцидента не открывались и не менялись.

## Общий путь

Используются существующие CreationService, PreparationPipeline, Preparation,
PreparedWorldValidator, AdventureLibrary, world resolver и launch_prepared.
Нового pipeline, движка или хранилища памяти нет.

1. Реальный upload PDF через `/api/creation/drafts/{id}/files`, ожидание извлечения.
2. Существующий `/prepare`: `world_structure=true`, `ruleset` редакции источника,
   `consent_to_send=true`, новый request_id. Это явный выбор полного структурного
   контракта PreparationBatch вместо компактного списка имён.
3. `prepared_start_readiness(preparation, draft_id)` — локальная безопасная проекция.
   `scope=world`; world_ready означает проверенную структуру, ready — отдельное
   подтверждение мира. Эти поля не подтверждают героя, механику, тариф или ключ.
4. `preparation.preparation_pipeline.confirm_world(draft_id, expected_revision=...,
   run_id=..., confirm=True)` возвращает существующий Draft с новой revision.
   Повтор того же подтверждения идемпотентен. Герой/предыстория подтверждаются
   существующими средствами; Native build валидирует существующий Nat20 preview.
5. `launch_prepared(..., confirm=True, expected_revision=..., build=...,
   encounters=..., mechanics_ruleset='dnd2024', rules_confirmed=True)` запускает
   выбранный Nat20-лист в этом мире. Далее обычный command-turn → GameCommand →
   GameEvent/GameSnapshot → проверяемый Narrator, save и восстановление.

`register_api` прежнего GM-адаптера принимает новые mechanics_ruleset/rules_confirmed
и необязательный encounters. Новые creation readiness/confirmation маршруты и
web-поток здесь не добавлялись: это владение Сборки/Интерфейса.

## Что изменено

- `preparation_contracts.py`: необязательный world_structure, по умолчанию false.
- `preparation_pipeline.py`: тот же block/resume механизм с существующими
  source_input/decode и полной схемой; source-world-v1 в fingerprint. Исходные
  параметры/контракт режима различаются, поэтому компактные имена не становятся
  кэшированной готовой структурой. Локальная проверка полного мира и confirm_world.
- `preparation.py`: сохраняемый world_confirmation; legacy launch не переключён.
- `prototype_prepared.py`: общий подтверждённый мир, разделение редакций, проверка
  обязательных стартовых зависимостей, защищённый replay и безопасная readiness.
- `tests/test_pdf_nat20_start.py`: синтетический настоящий PDF и целевые проверки.

SourceExtraction действительно умеет только name/location/start/source_spans.
Полного описания/знаний из этих имён нет. Его bracket/delimiter hotfix **не менялся**.
Новый режим использует уже имевшийся полный контракт и строгую проверку цитат,
публичного read-aloud, ссылок и обязательных элементов. Старый first_playable
остаётся отдельным legacy-входом; его документ-специфические guards не удалены
и не объявлены общим Nat20-стартом. Names-only старт и observation-only подстановка
не проходят подтверждение общего мира.

## Редакция, происхождение и ограничения механики

Сохранённая редакция источника/черновика не переписывается. Источник dnd2014 может
дать подтверждённые сюжет, локации и NPC для явно выбранной механики dnd2024.
Без mechanics_ruleset='dnd2024' и rules_confirmed=True такой новый старт отклоняется.
Новая кампания хранит source_ruleset, mechanics_ruleset, source_documents и ссылку
на run/хэш подтверждения. Исходная AdventureDefinition остаётся dnd2014.

NPC-знания проходят существующий scoped Memory Context Builder; source_ref
дополнен run_id, полные цитаты/provenance сохраняются в private результате
подготовки. Readiness не экспортирует их. Реплики остаются statements;
Narrator не создаёт мировые факты. Проверка канона и ACL сохранены.

Старые statblocks, таблицы, процедуры, трекеры и эффекты автоматически не
переносятся. Неподдержанная необязательная механика указывается отдельно и
не блокирует пригодный мир. Неизвестные обязательные элементы, start_conditions
и обязательная стартовая процедура без Nat20-привязки дают конкретный отказ.
Явно отложенная в другой локации процедура не приравнивается к обязательному
началу. Полного семантического доказательства произвольного пересказа валидатор
не обещает; `semantic_model_validation=false` сохранён.

## Оставшиеся стыки и точные границы

1. **Rules:** текущий PrototypeDefinition.encounters имеет min_length=1. Для
   подтверждённого мира без боя нужен min_length=0 с сохранением отказа на
   несуществующий encounter_id. Адаптер уже передаёт пустой словарь и не добавляет
   фиктивных врагов. Этот engine DTO здесь не менялся. До изменения этого стыка
   старт без единого профиля встречи не объявляется готовым.
2. Положительный smoke передаёт отдельную явно авторскую Nat20-встречу из прежней
   синтетической fixtures, чтобы удовлетворить текущий DTO. Она не извлечена из PDF,
   не запускается автоматически и не служит доказательством переноса statblocks.
3. **Сборка/Интерфейс:** подключить локальные readiness/confirm и новые поля к
   одному пользовательскому старту. Проверенный Python-контракт опубликован до
   реализации в PROTOTYPE_INTEGRATION.md. UI/end-to-end Windows здесь не проверялся.
4. Переход с компактного режима на структурный — новое явно запрошенное действие,
   с отдельным fingerprint/consent и теми же денежными guards. Старые блоки сохраняются;
   автоматической платной повторной отправки книги нет. Возобновление внутри режима
   переиспользует его проверенные части. Частичная книга не получает full-ready.
5. Живой ответ модели, качество произвольного PDF/box-layout, поздние обязательные
   процедуры, source statblocks и все классовые возможности этим smoke не доказаны.
   Legacy-кампании не мигрируются. Атомарность двух отдельных SQLite остаётся в рамках
   прежнего recovery-протокола; падение до записи world/draft-маркера не объявляется
   новым решённым глобальным протоколом транзакций.
