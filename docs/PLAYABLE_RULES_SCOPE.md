# Исполняемый игровой набор Nat20

Примечание preview.7: экран теперь предлагает «Второе дыхание», сцену можно
запустить из интерфейса. При 0 HP подтверждённое Nat20 состояние сохраняется,
но поддержанный сценарий останавливается до загрузки сохранения. Полные death
saves/спасение/смерть не подключены и результат не выдумывается. Проверки кнопок
выполняются одним disposable worker с отдельным replay каждого кандидата;
исполнение повторно валидирует команду. Полный каталог правил не расширялся.

Версия данных: `nat20-campaign-v1`, редакция `dnd2024`. Это ограниченный
игровой набор для человека-воина первого уровня, а не перенос всех PHB/DMG/MM.
Механика исполняется локальным закреплённым Nat20 0.7.0. UI, PDF pipeline,
cloud-бухгалтерия и исходный код Nat20 этой работой не меняются.

## Типизированная кампания

`integration/nat20/playable/registry.json` регистрирует определения по ID,
SHA-256 и статусу поведенческой проверки. До успешной проверки новые определения
разрешены только изолированному стенду `SOLO_TEST=1`.
`campaign.schema.json` соответствует `solo/nat20_campaign.py`.
Новая кампания создаётся доверенным Python API:

```python
api = Nat20GameEngine(store)
campaign = api.create_campaign(
    'Дозор', definition_id='fighter-standard-array-2024-v1')
```

Поддержаны два зарегистрированных билда: прежний проверенный воин
`fighter-road-2024-v1` (16/14/14/10/12/8) и воин со стандартным массивом
`fighter-standard-array-2024-v1` (15/13/14/10/12/8). Это готовые персонажи,
не универсальный конструктор происхождения, талантов и повышений характеристик.
У обоих обычные HP 12, AC 18, длинный меч, кольчуга, щит, Athletics и Perception.
Все производные характеристики рассчитывает `derive_sheet/build_party_member` Nat20.

Определение содержит `CharacterBuildSpec`, ID оружия и разрешённой особенности,
тип проверки/навык/Сл, `GridScene`, стартовые позиции, ID и шаблон противника,
бюджет опыта, ID награды и её источник. При исполнении сохранённое определение
сверяется с зарегистрированной версией. Изменение Сл, билда, состава встречи или
награды требует нового проверенного определения. Старые кампании без определения
сохраняют прежнюю механику и replay; новая способность и награда в них не появляются.

Сл 15/12/15 и бюджет 50 XP — авторские параметры сцены `solo-road-watch@1.0.0`,
а не извлечённая таблица PHB, автоматический расчёт CR или предложение LLM.
Гоблин берётся из проверенного шаблона Foundry, а не из присланных моделью статов.

## Поддержанные действия

| GameCommand.action | Поведение и ограничения |
| --- | --- |
| `check` | Зарегистрированные `athletics`, `perception`, `strength`; Сл и владения задаёт кампания/Nat20. Вне боя, без неподключённых модификаторов состояний. |
| `start_combat` | Только ID встречи из определения; один Goblin Warrior, закреплённая карта и позиции. Завершённая наградная встреча не запускается повторно. |
| `move` | Штатный `PlayerIntent(move)`, только поверхность z=0; дальность и допустимость проверяет Nat20. |
| `dash` | «Рывок»: штатный `PlayerIntent(dash)`, расход действия и дополнительное движение считает Nat20. Движение доступно до и после; повтор без действия отклоняется. См. `NAT20_DASH_SCOPE.md`. |
| `attack` | Штатный `PlayerIntent(attack)` с оружием кампании и зарегистрированным ID врага; попадание, урон, критический удар и экономику действий считает Nat20. |
| `use_feature` | Только `second-wind`: штатный `PlayerIntent(use_feature)`, лечение, бонусное действие и расход использования внутри Nat20. |
| `end_turn` | Штатный pass героя и `advance_monster_turn` до следующего решения героя. |
| `end_combat` | После устранения живых врагов; победа с живым героем закрывает бой и регистрирует единственную награду. |
| `short_rest` | Штатный `resolve_short_rest/recover_feature_uses`, доступная кость хитов и восстановление ресурса. |
| `long_rest` | Штатный `resolve_long_rest/recover_feature_uses`; сохраняется прежняя защита одного отдыха за 24 часа. |

Модель передаёт ID действия, проверки, встречи, цели или особенности, но не
характеристики, Сл, броски, урон, код, произвольный состав встречи либо XP.
Неизвестные действия и дополнительные поля отвергает закрытый контракт.
Неподключённые действия не заменяются похожими операциями старого движка.
Разрешённая схема инструмента сама по себе не гарантирует допустимость в текущем ходу.

## Награда, память и восстановление

`EncounterMemberSpec.xp_value` получает зарегистрированный бюджет опыта;
`CombatOutcome.xp_awarded` Nat20 определяет награду герою. Адаптер только
добавляет полученное значение в долговечный счётчик `experience` и сохраняет
`RewardReceipt` с ID встречи/боя, источником и хешем исхода. Уровень автоматически
не повышается. Денежные награды, торговля и выдача предметов не подключены.

Изменение состояния, общие `GameEvent/GameSnapshot`, ресурс XP и факты памяти
записываются одной существующей транзакцией `Store.engine_event`.
Нового журнала и отдельной памяти нет. В существующем перечислении команд
добавлены `use_feature` и `dash`; остальные контракты и ACL сохранены.
Одинаковый request ID возвращает прежний результат; иной смысл с тем же ID,
устаревшая версия и повтор награды отклоняются. Ошибка памяти откатывает награду,
завершение боя и событие. Checkpoint/undo восстанавливают ресурс и видимость
памяти соответствующей ветки.

Активный бой восстанавливается существующим проверяемым replay: инициатива,
текущий ход, позиции, HP, ресурсы, эффекты и результаты RNG сверяются до продолжения.
Сохраняется ограничение 256 команд на бой и запрет небезопасного частичного
восстановления. LLM остаётся автором предложения; Narrator получает подтверждённый
результат, а художественный текст не становится механическим доказательством.

## Исполнение и каталог источников

`capabilities.json` — перечень исполняемых возможностей и provenance 12 ранее
импортированных документов: Foundry dnd5e 5.3.3, данные SRD 5.2, редакция 2024,
CC-BY-4.0, исходный pack/document ID и хеши. Загрузчик проверяет закреплённые
исходники Nat20, версии зависимостей и контрольные суммы контента.

`search-catalog.json` — компактные метаданные всех 2 460 верхнеуровневых документов
девяти локально извлечённых пакетов Foundry. Генератор
`tools/index_nat20_catalog.py` читает активный MANIFEST LevelDB с учётом удалений;
не запускает JavaScript и не импортирует новые механики. У каждой записи
`executable=false`, `import_status=metadata_only`. Остальные пакеты доступны
на уровне manifests в прежнем `pack-inventory.json` (всего 40 Foundry/Laaru packs).
Это индекс доступных локальных источников, а не полный текст всех трёх книг.
Laaru 2014/HB/UA не превращается в 2024; новые материалы Laaru не активированы.

## Прежние маршруты

Они сохранены для обычных Solo-кампаний до общей приёмки. Для Nat20 мутации
перехватывает прежний `one_backend`: HTTP 409 `command_backend_required`.
Новый набор не использует эти механические обработчики:

- `/api/campaigns/{id}/play`, `/actions`; правка, отмена и подтверждение
  `/api/actions/{id}` и `/api/actions/{id}/{cancel,confirm}`;
- `/api/campaigns/{id}/screen/commands` старого экрана;
- `/api/campaigns/{id}/combat/{start,command,move-preview,fall-preview}`;
- `/api/campaigns/{id}/rest`, PUT `.../character`, `.../ruleset/{preview,apply}`;
- `.../inventory/command`, `.../merchants`, `.../trade/{quote,apply}`;
- `.../world/{preview,command,import}` и `.../hybrid-rules/{activation,proposals,checks}`;
- механические предложения `/api/events/{id}/proposals/{proposal}` и старый
  `/api/events/{id}/narrate`; подключение/продолжение материалов adventure/review.

Общие `/command-turn` и `/commands` выбирают Nat20 по `state.nat20`.
Служебные `/saves`, `/restore/{checkpoint}`, `/undo` остаются отдельными.
Прежние заметки/настройки/ручной `/dice` не применяют игровые последствия.
Изменение текста narrative события не меняет подтверждённую механику.
Прямой вызов `CommandEngine.execute` для Nat20 также запрещён.

## Проверки и границы

`tests/test_nat20_playable_rules.py`: обычный стандартный массив без усиления,
mock HTTP command-turn, проверка, полный бой, save/новый процесс/replay,
награда и rollback памяти, idempotence, отдых и повторный перезапуск,
нативное «Второе дыхание»/экономика/ресурсы, Schema, защита от подмены данных,
старое сохранение Nat20 и обычная Solo-кампания, отделение каталога.
JSON Schema проверяется существующим локальным PowerShell Test-Json.
Регрессии: `test_command_cycle.py`, `test_nat20_api.py`,
`test_nat20_command_cycle.py`, `test_engine_memory.py`.
Результаты сохраняются в `integration/nat20/reports/playable-*.xml/json`.
Приёмка 18.10.2026: **71 уникальный целевой тест прошёл**; отдельно проверены
создание зарегистрированной кампании, check и restore без `SOLO_TEST`.

Дополнение «Рывок» 18.10.2026: 76 уникальных целевых тестов прошли по последним
результатам; состав прогонов, контракт и ограничения — `NAT20_DASH_SCOPE.md`
и `reports/nat20-dash/results.json`. Это отдельный набор проверок, его число
не суммируется с предыдущей приёмкой.

Остаются неподключёнными: Action Surge (не первый уровень), Weapon Mastery,
выбор Fighting Style/талантов человека, заклинания, полный конструктор персонажа,
новые классы/уровни, встреча с несколькими противниками, смерть/спасение при 0 HP,
бегство/сдача, экипировка через inventory и сюжетные/world события.
Гоблин поддерживает проверенную ветку Scimitar; Shortbow, Nimble Escape и
условный дополнительный rider при преимуществе требуют отдельной привязки.
Такая ветка атомарно отклоняется. Это остающиеся работы по переводу поведения
Foundry в существующие операции Nat20, не основания для клиентской математики
или исполнения JS/кода из PDF/ответов AI.
Сохранено штатное автоматическое продвижение хода Nat20 после некоторых intents;
проверенный путь «Второе дыхание → атака» не обещает произвольный порядок
бонусного действия после авто-завершённой атаки. После единственной встречи
можно отдыхать и выполнять проверки; следующая встреча требует новых проверенных данных.
