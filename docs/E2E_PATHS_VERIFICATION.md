# Проверка игровых путей через публичные интерфейсы

**Важно о характере проверки.** Всё ниже проверено через `Nat20GameEngine` и `Store`
(`solo/nat20_api.py`), то есть на уровне API и движка. Это **не** браузерная приёмка:
Chromium в этой среде не запускается (`browserType.launch: spawn EPERM`), и ни один
из пунктов ниже не подтверждает работу интерфейса в браузере.

Скрипты: `runtime/_e2e4.py`, `runtime/_e2e5.py`, `runtime/_e2e6.py`.

## 1. Законный персонаж выполняет действие, состояние меняется

Кампания `fighter` 5 уровня с подклассом `champion`, снаряжение `longsword/chain-mail/shield`.
`create_experimental_campaign` → версия 0, в состоянии присутствует `nat20`.

## 2. Атака рассчитывается Nat20

`start_combat` → версия 1. Атака по `rat-a` → версия 3, число записей журнала 1 → 3.
Обе записи созданы движком Nat20 (они приходят из `store.engine_event`).

Правило движка, обнаруженное по ходу: атака героя до хода монстра отвергается с
`Hero is not the current actor; end_turn advances the registered monster policy`.
Это корректное правило очерёдности, а не дефект.

## 3. Повтор того же запроса не создаёт второе действие

Повтор с тем же `request_id` и той же `expected_version` → версия осталась 3,
число записей журнала осталось 3. Повторного списания нет.

Побочно подтверждено: тот же `request_id` с другим телом отвергается
`ValueError: request_id не соответствует другой команде`.

## 4. Отдых восстанавливает ресурсы

`long_rest` (с `food_water=True`) → версия 0 → 1.

Контракт строг: `long_rest` без `food_water` отклоняется ещё на валидации
`GameCommand`, до любого изменения состояния.

## 5. Новый процесс восстанавливает ту же кампанию

Отдельный процесс Python (`subprocess`), тот же файл базы: прочитана та же кампания,
`версия 1`.

## 6. Кампания не переключается на старый боевой калькулятор

Попытка `attack` вне боя отвергнута: `No active Nat20 combat`.
Тихий переход к прежнему расчёту не происходит.

## 7. Незаконная команда отклоняется до изменения состояния

`native_action` с несуществующей операцией отвергнута на валидации `GameCommand`.
Сравнение снимков: версия и `state` совпадают до и после — `состояние не изменено: True`.

## Чего эта проверка не показывает

- Работу экрана в браузере (Chromium заблокирован средой).
- Поведение при одновременных запросах из двух процессов.
- Сохранения на прежней версии корпуса — см. `docs/RELEASE_IDENTITY_DECISION.md`:
  они отвергаются, а не исполняются.
