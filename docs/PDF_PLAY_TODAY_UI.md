# PDF → подготовка → герой → игра: UI готов

18 октября 2026. **UI READY / source freeze**. Production-изменения ограничены `web/creation.js` и `web/prototype.js`; добавлены собственные проверки. Backend, Game Engine, каталог, память, API-контракты и защищённая `.3 dist` не менялись. Пользовательские профили и project DB/WAL не открывались. Full/EXE/live/paid — **0**.

## Исправления

- Продолжение берёт `preparation_mode` и `source_ruleset` из серверного status/latest по [контракту](PDF_PREPARATION_RESUME.md). Старые локальные подсказки режима больше не используются. `world_structure` сохраняется после закрытия, нового процесса и пустого browser storage; `source_extract` отправляет явный `world_structure:false`. Известная редакция источника заблокирована от случайной смены.
- `unknown` требует явного выбора режима; неизвестная редакция — явного выбора редакции. Отмена возвращает управление. Смена run/mode/редакции или revision после открытия согласия блокирует устаревшую отправку. На время отправки выбор заморожен, двойной клик не дублирует запрос.
- Новая полная подготовка остаётся отдельным действием с тарифным согласием и новым request_id. Просмотр прогресса/readiness и ошибки readiness не запускают AI или prepare fallback. Names-only 31/37 не становится готовым миром; историю ошибок и актуальную проверку UI показывает отдельно.
- Кнопка материалов в конструкторе возвращает к **тому же** серверному черновику. Имя, лист, предыстория и три явных подтверждения сохраняются при возврате. После повторного открытия Native preview нужно выполнить заново; изменённый мир требует актуального подтверждения.
- Прерванный ответ запуска переживает reload: сохраняются точный payload и request_id. Если сервер уже создал связанную кампанию, повтор проходит через его существующую проверку/replay и открывает единственную кампанию. Известный успешный ответ не вызывает повторное создание при сбое обновления экрана.
- Готовый мир без боя передаётся с `encounters={}`. Источник 2014 и выбранная механика 2024 разделены; герой, предыстория и 2024 подтверждаются отдельно. Расчётов листа/боя в JS нет. Статус `configured` корректно распознаётся конструктором как доступный облачный профиль.

В реальной приёмке браузер использует настоящие registered API и Nat20. AI — **offline MockTransport**, не живой провайдер. Через обычные кнопки «Новая игра» → материалы загружен настоящий четырёхстраничный **синтетический PDF**:

1. Явная полная подготовка завершилась частично: **1/2**, второй блок получил заданный HTTP 503. Мир остался заблокирован.
2. Новый процесс и пустой browser storage: черновик открыт из «Моих приключений»; resume сохранил `world_structure`/2014. Transport получил **только batch 1**, ранее принятый блок сохранил прежние ID/body. Итог — **2/2**.
3. Проверка и подтверждение мира → human Rogue → Native preview и три подтверждения. Возврат в материалы сохранил draft/revision/имя/предысторию; фиктивный враг не добавлялся.
4. Настоящий `/prototype/campaigns` создал кампанию, затем тест оборвал **только доставку ответа**. После reload повтор отправил идентичный payload/request_id; сервер подтвердил **ровно одну** кампанию. Игровые ответы не подменялись.
5. Осмотр → диалог с NPC со знанием о мосте → native dex saving throw → служебное сохранение. Третий процесс и ещё один пустой browser context: запуск из списка приключений, полный canonical snapshot совпал; сервер сравнил хэш Nat20 state; wis saving throw увеличил версию **4 → 5**. `memory.audit` без замечаний.

Ошибок JavaScript **0**, legacy `/play`/`character/confirm` вызовов **0**, подготовительных запросов при третьем запуске **0**, реальных AI-вызовов **0**. Первые два запуска нового harness упирались в наследуемый Windows stdin: блокирующее ожидание родителя задерживало запуск import worker. Harness переведён на собственный stop-marker и DEVNULL, production importer не менялся; окончательный прогон прошёл полностью.

Прежние четыре UI-проверки и `.3` приёмка использованы как baseline, полный набор не повторялся. В собственных старых fixtures обновлены явные metadata и селекторы диалога под новый контракт; их старые времена не выданы за новые прогоны.

## Границы

- Пользовательская книга и живой облачный ответ не проверялись. Новое платное полное извлечение не запускается автоматически. Reuse при другой модели/параметрах/материалах определяет серверный fingerprint.
- Это source/browser приёмка, не новая EXE или загрузка Drive. `.3` snapshot/dist сохранены без изменений.
- Неподдержанная обязательная механика блокирует мир по серверной причине. Исходные statblocks/эффекты не переносятся автоматически. Последующий стык auto-native monster binding уже подключён: выбранный `native_derived` показывает готовый бонус/источник и не отправляет ручной override; `unbound` показывает причину и необязательный авторский ввод. JS ничего не рассчитывает. Итоговый реальный browser/API smoke: **1 passed, 24.09 с**; подробности в [NAT20_MONSTER_UI.md](NAT20_MONSTER_UI.md), [trace](../reports/monster-profile-ui/results.json), [Wolf](../reports/monster-profile-ui/native-wolf.png), [unbound Knight](../reports/monster-profile-ui/local-unbound.png).
