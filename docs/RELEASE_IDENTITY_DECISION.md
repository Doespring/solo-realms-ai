# Идентичность релиза и старые сохранения — решение

## Что такое `374afd1a…`

`release()` в `solo/nat20_content.py:162` считает отпечаток как
`digest({runtime: хеши .py движка, content: манифест, dice_versions})`.

Значение `374afd1a3898e089e023130cc342a0f3c6fe88a75bf4f8ee7e3bf865852abf75` соответствует
состоянию, в котором одновременно были:

- прежние байты `.py` движка (до правок в `dnd5e_engine/activities/{context,damage,dice,formula}.py`
  и `dnd5e_srd_data/loader.py`);
- прежние байты содержимого корпуса (1674 изменённых файла `vendor/nat20` в рабочем дереве).

## Доказательство, что родитель не восстановим в текущем дереве

1. Манифест релиза `integration/nat20/releases/prototype-srd-2024-v1/manifest.json` менялся
   только в коммите `9723a04`.
2. В `9723a04` **нет каталога `vendor/nat20` вообще** (`git ls-tree -r 9723a04 -- vendor/nat20`
   пуст), то есть эталонного снимка корпуса в истории не существует — восстановить нечего.
3. Родительский **манифест содержимого не менялся**: `parent_manifest_sha256` из Bless-манифеста
   `37841f2920b7924a1b19e09dd5b75c1821b35ef311216677414c391f80f32e56` совпадает с текущим
   `integration/nat20/imported/manifest.json`. Значит расхождение дают не описи, а байты `.py`
   движка и содержимое документов.

## Принятое решение

**Понятный отказ без изменения сохранения.** Миграция не выполняется: я не могу доказать, что
старые сохранения сохраняют смысл на новых байтах (изменились и правила движка, и содержимое).
Новый отпечаток в старую фикстуру не подставляется.

- Старая фикстура `tests/fixtures/nat20-preview7-fighter-combat.json` остаётся нетронутой
  с `release_digest = 374afd1a…` как запись о байтах, на которых играли ту кампанию.
- Кампания с этим отпечатком **не исполняется**: `solo/nat20_worker.py:229` отвергает состояние,
  у которого `release_digest` не равен текущему отпечатку.
- Отказ происходит **до** любой записи: `create_campaign` → `solo/nat20_api.py:153` поднимает
  `ValueError: Bless content parent/edition mismatch; no implicit migration`, кампания не создаётся,
  версия состояния не меняется.

## Два независимых факта, которые нельзя смешивать

| факт | значение | что означает |
|---|---|---|
| фикстура сохраняет своё | `374afd1a…` | запись о прошлых байтах, менять нельзя |
| живой корпус сейчас | `33359fe3538b96bdb1bbde77b5d1d6aa8769d2fe2a2c65f66eb282de5a4bf394` | байты, которые реально исполняются |
| Bless-манифест ссылается на | `374afd1a…` | родитель, которого в дереве нет |

## Следствие для Bless

Расширение `bless-self-2024-v1` привязано к родителю, которого нет. Это **вне зоны этого потока**:
перепривязка означает новое решение о релизе корпуса. Подготовлена передача
`docs/HANDOFF_BLESS_PARENT_PIN.md` с воспроизводимым примером.

## Как воспроизвести

```powershell
$env:SOLO_TEST='1'; $env:SOLO_NAT20_BLESS_STAND='1'
.venv\Scripts\python.exe runtime\_bl3.py
```

Ожидается: `ValueError: Bless content parent/edition mismatch; no implicit migration`.
