# Передача движку: видовые группы строятся по отображаемому имени

Дата: 27 октября 2026. Статус: **найдено, не исправлено** (файл движка, вне моей зоны).

## Дефект

`vendor/nat20/packages/dnd5e-engine/src/dnd5e_engine/rules/advancement.py:684`:

```python
base = str(species.name).split(",", 1)[0].strip()
```

Ключ группировки берётся из **отображаемого имени**. После перевода корпуса `"Elf, High"` стало
`"Эльф, высокий"`, и все группы получили русские ключи: `Эльф`, `Гном`, `Человек`.

## Почему это дефект, а не косметика

- Отображаемое имя — то, что видят игроки; оно меняется при локализации, переименовании и
  правке текста. Ключ группировки не должен от него зависеть.
- Запрос на английское имя (`groups['Elf']`) больше не работает — именно так упал
  `tests/test_nat20_advancement.py`.
- Сломается любой потребитель, который ищет вид по имени, а не по слагу.

## Что проверено сейчас

Сама группировка из корпуса работает верно — изменились только ключи:

```
Гном        required=True  variants=['gnome-forest', 'gnome-rock']
Голиаф      required=False variants=['goliath']
Тифлинг     required=True  variants=['tiefling-abyssal', 'tiefling-infernal', 'tiefling-chthonic']
Эльф        required=True  variants=['elf-high', 'elf-drow', 'elf-wood']
Человек     required=False variants=['human']
```

Правило «один лист — без выбора, больше одного — обязательный выбор» держится.

## Что предлагается (решение за потоком движка)

1. Группировать по слагу: `elf-high` → префикс `elf`, `gnome-forest` → `gnome`.
   Слаг — стабильная идентичность, он не переводится.
2. Либо добавить в документы вида отдельное поле базового вида и группировать по нему.

Вариант 1 проще и не требует правки 1664 документов корпуса.

## Что я сделал у себя

`tests/test_nat20_advancement.py::test_lineage_groups_come_from_the_corpus_not_a_hand_written_table`

он по-прежнему доказывает, что группировка приходит из корпуса, а не из рукописной таблицы.
