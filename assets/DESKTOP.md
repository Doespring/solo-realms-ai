# Windows Desktop 2.1.0-preview.1

Obsidian Chronicle: 65 локальных ресурсов с миниатюрами/лицензиями, отдельный неизменённый Asset Catalog, подготовка кампании/героя и отдельные настройки. Встроенные проверки frozen EXE подтвердили локальные хеши/шрифты/индекс источника, масштабы 100/125/150 и фактический обработчик выхода. Схема 10, источник/черновики хранятся отдельно от canonical campaign journal. Groq остаётся выключенным до настройки пользователя; реальные вызовы в этом выпуске не проверялись.

Готовы portable-каталог `dist/SoloRealmsAI/` и установщик `dist/SoloRealmsAI-Setup-2.1.0-preview.1.exe`. Python 3.12 и backend находятся внутри сборки. Запуск — SoloRealmsAI.exe или Desktop.cmd из проекта. Отдельное окно WebView2 открывается без внешнего браузера/FastAPI-команды. Параметры окна/полноэкранный режим/F11, масштаб интерфейса, резервная копия доступны в панели. Сценарный код, модели, KoboldCpp, голос, музыка, реальные API-ключи и пользовательские кампании в дистрибутив не включены.

Нужны Windows 10 build 19041+ / Windows 11, x64 и Microsoft Edge WebView2 Evergreen Runtime. Python вручную устанавливать не нужно. На этой машине Runtime уже установлен. При отсутствии Runtime установщик сообщает об обязательной зависимости и даёт официальный адрес загрузки; он не подменяет Chromium старым IE. Принцип упаковки — [pywebview](https://pywebview.flowrl.com/guide/freezing); зависимость/обнаружение — [Microsoft](https://learn.microsoft.com/en-us/microsoft-edge/webview2/concepts/distribution).

Установка без администратора: `%LOCALAPPDATA%/Programs/SoloRealmsAI`. Профиль: `%LOCALAPPDATA%/SoloRealmsAI`. Здесь SQLite кампаний/расходов, профили/DPAPI ciphertext, настройки окна, WebView2 preferences и backups. Ключ защищён Windows CurrentUser DPAPI и остаётся на сервере. Сохранения пишутся транзакционно; первая загрузка новой версии делает coherent SQLite backup перед миграцией. После корректного закрытия — новая копия. Ручная кнопка делает ту же копию, включая расходы/защищённые ключи. Копии не удаляются автоматически.

Повторная установка с тем же AppId обновляет только файлы приложения. Перед обновлением закройте игру. Удаление не уничтожает отдельный профиль. Автопроверка/автозагрузка версий и сервер обновлений не настроены; реально доступный механизм — новый установщик. Новая схема блокирует старое приложение вместо миграции назад. Сборка экспериментальная и без цифровой подписи издателя.

Legacy import — явный CLI `SoloRealmsAI.exe --import-data-dir ".../старый проект/data"`, только в пустой профиль. Существующие данные не перезаписываются. Копируются лишь основные БД/профили/DPAPI; резервные архивы, QA, модели и логи остаются в исходном проекте. Backend не обращается к API при запуске. В текущем цикле восемь кампаний перенесены копией, исходная база сохранена. Браузерный Start.cmd использует прежний `data/`; это отдельная копия. Для дальнейшей игры через EXE используйте Windows-профиль, не чередуйте две копии как одну кампанию.

Desktop backend слушает только 127.0.0.1, выбирает незанятый порт и сохраняет его. Одноразовый bootstrap устанавливает HttpOnly/SameSite cookie; неавторизованный клиент получает 403. Нет общего Python/JS file/shell bridge; только валидируемые размеры/полноэкранный режим/backup через локальный API. Чужие Origin и навигация окна на внешний URL заблокированы. Mutex и файловая блокировка защищают профиль от второго EXE/одновременной установки.

Проверки: source host; frozen EXE без Python в PATH/PYTHONHOME/PYTHONPATH; установленный EXE; размер 1024×720/полноэкранный/возврат; mock-путешествие 30 минут; cookie/403; shutdown без оставленного backend; повторная установка/удаление с неизменным хешем тестовой SQLite; копии/WAL/DPAPI/version/lock тесты. Это запуск на текущем Windows-компьютере с установленными .NET и WebView2. Чистая VM без Python **не проверена**, ручная визуальная проверка native-окна средствами автоматизации недоступна. Качество/TTFT реальных облачных моделей не проверено по установленному пользователем ограничению.

Сборка: `.venv/Scripts/python.exe -m pip install -r requirements-desktop.txt`, затем `powershell -File scripts/build_windows.ps1`. Inno Setup 6.7.3 установлен только в проектном build-tools; источник [официальная загрузка](https://jrsoftware.org/isdl.php), подпись Pyrsys B.V. проверена. `scripts/verify_windows.ps1` проверяет установщик в изолированных project/data каталогах и откажется менять существующую пользовательскую установку. Пакет включает notices зависимостей и SRD attribution. Лицензия коммерческого использования Inno Setup определяется отдельно условиями разработчика; покупок не выполнялось.
